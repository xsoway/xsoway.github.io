1. 业务实现流程

  • 待测类型：
    • 单次查询
    • 上下文查询 (是否批量验证待定)

二、评测数据集

1. 测试数据类型覆盖

核心条件(业务字段)（13类）：

  • 年款（车龄）、品牌、价格、颜色、车身结构
  • 公里数（行驶里程）、过户次数、排放标准
  • 座位数、燃油类型、驱动方式、国别、变速箱

2. 边界场景测试

  • 18类用例场景（100%覆盖）
  • 样本分布：
    • 总量：1000条
    • 按类别权重分配样本量

3. 输入类型

  • 业务特点+数据构造设计倾向
类型 占比 特点
语音转文字 70% 口语化表达
格式化文字 30% 结构化/半结构化输入

4. 提示词(部分)

三、核心评估指标

概览

类型 指标 通过过标准
数据集 用例类型覆盖率 100%
结构化提取指标 精确率/召回率/F1
结构化提取指标 字段级别准确率 100%
容错能力 鲁棒性(0.1 ~ 1.0) 0.9
性能 模型平均响应时间 ≤ [阈值]ms
性能 端到端响应时间 ≤ [阈值]ms

1. 结构化提取指标

指标 计算公式 说明
Precision 正确字段数/提取字段总数 提取准确性
Recall 正确字段数/应提取字段总数 覆盖完整性
F1-score 2*(P*R)/(P+R) 综合评估

抽样分析：

  • 字段级准确率（如颜色提取正确率）
  • 关键字段加权（品牌/价格权重 > 国别等字段）

2. 查询结果验证

  • 车源数据准确性（人工校验）
  • 返回结果数量正确性

3. 性能与鲁棒性

指标 测量内容
容错能力 处理错别字/别名/语序颠倒的能力
多轮会话(待定) 上下文连续处理能力

四、通过标准

1. 样本类别(15类)

  • 正常类 (正向用例 / 基础用例 / 一般用例):

    1. 单条件查询：只使用一个筛选条件，是最基础的用例

    2. 多条件组合：两个及以上条件组合，是核心业务逻辑

    3. 全部条件：填写所有字段，测试系统是否全面支持

    4. 用户意图识别：一般用于验证是否能提取关键字段

    5. 地域相关性：如“北京能买的车”，虽稍复杂，但属于常见需求

    6. 多值并列条件：如“要白色或黑色”，结构明确，逻辑合理

  • 容错类（复杂用例 / 异常 / 极端 / 容错能力验证）

    1. 包含错别字：如“本驰”、“百马”，考查容错纠错能力

    2. 数字格式变化：如“十万”、“10k”、“10w”，需规范化处理

    3. 口语化表达：如“来辆能开得住的SUV”，语义不标准

    4. 条件冲突：如“奔驰3系”，字段间逻辑矛盾

    5. 特殊格式字符：如包含 emoji、标点、半角全角混排等

    6. 边界值：如价格 = 0、公里数 = 100000，验证上下限处理

    7. 异常情况：如语义模糊、不完整、系统无法识别的输入

    8. 条件模糊表达：如“预算差不多5万”、“公里数不要太多”

    9. 隐含否定条件：如“不要电车”、“非白色”，否定式表达需处理

类别 占比 样本量 准确率要求 其他要求
正常类 70% 700 P/R/F1=100% 全条件覆盖
容错类 30% 300 P/R/F1≥90% 鲁棒性≥0.9 (容错类别用例正确数/容错类别用例总数)

2. 性能标准

  • 模型平均响应时间 ≤ [阈值]ms
  • 端到端响应时间 ≤ [阈值]ms

五、标准设定建议(other)

1. 两种场景标准

  1. 强约束验证集（回归测试）：

    • 要求：F1=1.0
    • 适用：核心业务逻辑验证

  2. 弱约束泛化集（灰度测试）：

    • 要求：P≥0.95, R≥0.90, F1≥0.92
    • 适用：模型迭代评估

2. 优化建议

  • 错误样本分类分析（FP/FN类型）
  • 核心字段单独达标（如品牌/价格F1≥90%）
  • 避免设定”100%全达标”的非现实标准

模型验证示例分析

一、测试用例

1. 输入查询

Query: 查下2025款宝马3系, 30万以下的 白色的

2. 预期输出（Ground Truth）

3. 模型实际输出

二、维度分析

  1. 字段存在性

    • 多提字段：无
    • 少提字段：color（漏提）

  2. 字段值一致性

    • 正确值：year, mileageTo
    • 错误值：keywords（应为”宝马3系”但输出”宝马”）

三、评估指标计算

指标 计算过程 结果
Precision 2个正确字段 / 3个提取字段 67%
Recall 2个正确字段 / 4个应提字段 50%
F1-score 2*(0.67* * 0.5)/(0.67+0.5) 57%
指标 结果
用例覆盖类型 [“多条件组合”] “正向用例(正常类别)”
结果是否正确 Fail
鲁棒性(容错能力) 容错类别正确数/所有容错类别用例数 如: [“特殊格式字符”]
模型响应时间 api 请求 -> predicted提取结果返回时间

四、混淆矩阵分析

类型 说明 数量 对应字段
TP 字段存在且值正确 2 year, mileageTo
FP 字段存在但值错误 1 keywords（”宝马”≠”宝马3系”）
FN 应提未提 + 值错误 2 color漏提 + keywords值错误

5. 🔹返回 overall_res

  • 期望值
  • 预测值

六、问题总结

  1. 主要错误：
    • 品牌型号识别不完整（缺失”3系”）
    • 完全漏提颜色字段
  2. 优化方向：
    • 加强复合名词识别（品牌+车型）
    • 提高颜色等显性特征的提取能力
