# Zed 解读：90k 星的开源编辑器，敢让多个 AI Agent 同时开工

2026 年再聊"用哪个编辑器"，问题早就不是"能不能写代码"，而是"编辑器能把几个 AI 角色同时请进来、还能不和你的队友打架"。市面上各家都在往编辑器里塞 AI，但多数是"绑定自家一个助手"的路子。这次要看的 `zed-industries/zed` 走的是另一条路：它把"接哪个 AI"这个决定权交还给了协议，让你自己带 Claude、Codex、Gemini，还能让它们并行干活。

先给结论：这是一个 **Rust 写的、GPU 加速、自带多人实时协作、并开放了 AI 交互协议（ACP）** 的开源编辑器，GitHub 上 **9 万+ star、1.1 万 fork、4 万+ 次提交**，由 Atom 和 Tree-sitter 的原班人马创建。下面先说它和常见编辑器的区别，再讲它是什么、怎么用，最后从测试开发视角聊聊它带来什么价值。

## 和其他编辑器比，差在哪

| 编辑器 | 底层 | 花钱吗 | 在哪用 | 主要帮什么 | AI 能不能并行 |
| --- | --- | --- | --- | --- | --- |
| VS Code | Electron（Web 技术） | 免费 | Win/macOS/Linux/网页 | 插件生态最全，AI 靠 GitHub Copilot | 基本单助手，靠扩展 |
| Cursor | 基于 VS Code 改 | 付费为主（Pro $20/月） | Win/macOS/Linux | 把 AI 编辑深度做进原生体验 | 有限，重心在单 Agent 对话 |
| JetBrains 全家桶 | JVM | 订阅付费 | Win/macOS/Linux | 强类型语言的重构/导航 | 收编 ACP，最近才谈开放互通 |
| Zed | Rust + 自研 GPU 引擎 | 编辑器本体免费 | macOS/Linux/Windows（网页暂无） | 原生快 + 多人协作 + 自带 Agent | 原生支持多个 Agent 并行、多工作区 |

单看每一行，Zed 不像谁出了绝招：VS Code 免费、Cursor 聚焦 AI、JetBrains 重构强。它的组合拳在别处——**同时做到"原生性能 + 真多人实时编辑 + 一个开放的 AI 协议把各家 Agent 都收进来"**。这几件事单拿一样都不稀奇，凑在同一个开源编辑器里就不多了。

## 它是什么

Zed 是一个开源代码编辑器，语言是 Rust，用自研的 GPU 渲染引擎（项目里叫 `gpui`）做界面，所以启动和打字都很快——文档里的描述是"为性能和协作从零打造"。它不是套壳改的，是真正从头写的。仓库里除了主体代码，还有 `crates/`、`docs/`、`extensions/`、`tooling/` 这些目录，典型的完整编辑器官。

**做什么用的**，简单说三件事：

1. **写代码**：内置入门语言支持，更多语言靠装扩展；支持 Vim 模式，键盘流用户能无缝接。
2. **多人实时协作**：几个人能同时编辑同一个项目，看到彼此的鼠标和实时改动，还能开语音。这是它一开始就主打的能力，写作 "multiplayer code editor"。
3. **接 AI Agent**：它自带一个 Zed Agent，同时开放了 **ACP（Agent Client Protocol）**，让外部 Agent（Claude Code、Codex CLI、Gemini CLI、GitHub Copilot 等）都能以统一协议接进来。

**怎么用**：官网 `zed.dev/download` 下载对应系统版本，`Cmd+Shift+A`（Win/Linux 是 `Ctrl+Shift+A`）打开 Agent 面板，`Cmd+Enter` 做行内 AI 辅助，`Ctrl+Shift+C` 打开协作者面板。编辑器本体免费，AI 部分可以带自己的 API key，也可以订阅它的 Pro（$10/月）。

## 白话说说它好在哪

换个视角看这几个特点，Zed 的三个特点其实都踩在"减少摩擦"上。

**第一个，快，是真原生快。** 很多编辑器是拿网页技术套个壳，快是"看起来快"。Zed 不一样，界面从底层就是 Rust 写的，借 GPU 渲染，能压满多核。对天天打开几百兆项目、来回切文件的人，启动那一下和滚长文件的跟手度，区别是能体感到的。这不是玄学，是"从高效利用多个 CPU 核心出发"做出来的结果，仓库作者写在页面介绍里。

**第二个，多人协作是它从第一版就带的，不是后加的补丁。** 它天生支持"几个人同时改一个项目"，实时看到对方光标和改动，还能建"频道"当常驻协作房间，房间里有共享项目、语音。对需要结对编程、远程评审的团队，这个比"把屏幕截屏发群里"强太多。

**第三个，也是 2025 到 2026 最出圈的：它把"接哪个 AI"做成了开放协议。** 2025 年 8 月 27 日，Zed 带着 Google 的 Gemini CLI 作为第一个接入方，发布了 ACP（Agent Client Protocol）。这个协议是 Apache 开源的，意思是：任何只要愿意讲 ACP 的 Agent，就能接进任何支持 ACP 的编辑器，不用某一家单独做定制集成。现在协议生态里，编辑器有 Zed、VS Code、JetBrains、Neovim、Emacs、Obsidian；Agent 有 Claude Code、Codex CLI、Gemini CLI、GitHub Copilot、Cline、Goose、Devin、Qwen Code、Kimi CLI 一大串。JetBrains 也在 2025 年 10 月和 Zed 一起参与这个开放互通。

**对普通用户来说，这第三个特点意味着什么？** 意味着你不再被锁在某一家 AI 上。今天想用 Claude、明天想换 Codex，装个对应 Agent 就行；甚至能同时开好几个 Agent，分别去不同的项目或工作区干活，看到它们的进度。用第三方 Agent 时，数据不经过 Zed 的服务器，隐私边界更干净。

## 从测试开发视角看，它带来什么

编辑器的选型只是表面，Zed 真正让测试和工程侧多想的，是"**AI Agent 怎么和既有开发与测试流程协作**"这件事。

**第一层，Agent 变成可并行、可观测的"协作者"。** 测试同学最怕的场景之一是"改了个接口，一大片用例受影响，要人肉排查牵连范围"。Zed 支持多个 Agent 并行干活、多个工作区，这给了个新组织方式：让一个 Agent 去改动 A 模块、另一个去 B 模块，测试侧盯住两个工作区的变更和运行结果，而不是一个人串行等完再等下一个。并行不等于乱，关键是围绕"一个项目多工作区"的机制来约束边界。

**第二层，ACP 把"接哪个 Agent"从编辑器决策变成了工程决策。** 之前想给团队配 AI 助手，往往被绑死在某一家。有了通用协议，测试工程可以按场景挑 Agent：写用例用擅长代码生成的，跑回归用能直接调终端的，甚至接入自家基于 ACP 的 Agent。组合是团队定的，不依赖某家编辑器闭源锁死。

**第三层，多人实时协作对测试的价值，是把"评审"做成了实时动作。** 测试开发最常做代码评审和接口联调。Zed 里能实时看到别人改动，pair 着改测试用例、一起盯一个报错，效率比截图+语音来回传高。它把协作从"异步提 PR 等人看"的边缘，又往"实时一起改"这边拉了。

当然也要落回现实：Zed 现在是 macOS/Linux/Windows，**网页版还没有**（仓库里有跟踪讨论）；迁移老项目要装语言扩展。日常验证它完全够，但要不要当主力编辑器，得看团队现有的工具链和协作习惯能不能接上。
