# **用 Codex 装 Skill，再用 Skill 一键写公众号：5 分钟让 AI 给你打工（附踩坑提醒）**

从 **brew 升级 Codex → 安装 Skill → 查看 Skill → 调用 Skill 写公众号文章**，完整实战一遍。

你照着做，基本 5 分钟之后就能体验到什么叫：

> **“不是我在写公众号，是 AI 在替我还债。”**

## **一、先升级 Codex：不升级就像用诺基亚装微信**

开始之前，先来一发升级，避免后面出现那种最让人崩溃的情况：

> 你明明照着教程做了，但它就是不工作。

> 然后你开始怀疑自己、怀疑人生、怀疑这个世界是不是只有你被针对。

执行：

```
brew upgrade codex
```

✅ 为什么要升级？

说白了三个字：**省时间。**

- 获取最新修复
- 避免奇怪兼容性问题
- 后面 skill list、交互界面更稳定

工具这种东西，版本落后一点点，你排查 bug 就能多掉一撮头发。

## **二、安装 Skill：把它丢进 Codex 的“技能口袋”**

Codex 的 Skill 机制其实很朴素：

* *一个 Skill 就是一个文件夹，核心就是一个 skill.md。**

你要做的事也很朴素：

把它放进指定目录。

直接上命令：

```
mkdir -p ~/.codex/skills/wechat-article-generator
cp SKILL.md ~/.codex/skills/wechat-article-generator/skill.md
```

### **✅ 解释一下这两句话到底干了啥**

#### **1）创建 Skill 文件夹**

```
mkdir -p ~/.codex/skills/wechat-article-generator
```

这里的关键点是：

- ~/.codex/skills/ 是 Codex 默认识别 Skill 的目录
- wechat-article-generator 就是你 Skill 的名字（文件夹名）

你可以理解为：

你在 Codex 的身体里装了一个器官，名字叫 wechat-article-generator。

#### **2）把你的 SKILL.md 复制过去，并改成 skill.md**

```
cp SKILL.md ~/.codex/skills/wechat-article-generator/skill.md
```

Codex 对文件名很“龟毛”。

它不管你原文件叫啥，最终它就认一个：

✅ skill.md

所以你这里相当于：

> “把原来的技能说明书，翻译成 Codex 能看懂的格式。”

## **三、验证 Skill 是否安装成功：别急着兴奋，先确认它活着**

装完 Skill 之后第一件事不是“我来写爆款”，而是：

* *确认它被 Codex 识别到了。**

执行：

```
codex skill list
```

你会看到类似这样的输出：

- wechat-article-generator
- skill-creator
- skill-installer

Codex 还会顺便告诉你每个 Skill 是干嘛的，比如：

- **wechat-article-generator**：交互式公众号文章生成器（确认主题 → 给大纲 → 写全文 → 配图规划）
- **skill-creator**：创建/更新 Skill
- **skill-installer**：安装精选 Skill

✅ 如果你能看到它的名字，就说明：

* *你已经把 Skill 成功植入 Codex 的大脑皮层了。**

## **四、常见踩坑：为什么它提示 “Tried opening SKILL but reading timed out…”？**

你日志里有一句很有灵魂的话：

> Tried opening SKILL but reading timed out…

翻译成人话就是：

> “我想打开某个文件，但我读着读着累了，我就睡着了。”

这一般不是什么毁灭性 bug，更多是：

- Codex 读某个文件的时候超时
- 或者路径/文件名识别不规范
- 或者文件内容太长/太复杂它不爱看

### **✅ 建议排查点（都是真·踩出来的经验）**

你可以按这个顺序排查：

1. **是不是有个文件叫** **SKILL****（没后缀）在那儿碍眼？**

2. **skill.md 太大了或者写得像百科全书？**

3. **权限问题（复制文件时偶发）**

4. **路径必须严格是：**

   ~/.codex/skills/<skill-name>/skill.md

一般来说，只要你能 codex skill list 正常看到 Skill，它就能用。

## **五、真正爽的地方来了：用 Skill 一键写公众号文章**

Skill 装上了，你就可以开始做一件很爽的事：

> **用一句话，让 Codex 给你写文章。**

在交互界面输入：

```
$wechat-article-generator 帮我写一篇主题为: 《我想坚持写公众号，但我不知道写什么》的文章
```

然后你就能看到 Codex 开始进入“主编模式”，先确认主题、受众、痛点，再给你出大纲，最后写全文。

你可以理解为：

> “你不是在写文章，你是在雇佣一个编辑部。”

### **✅ 这个结构你可以无限复用**

公式就是：

> $SkillName + 你的需求

例如：

- $wechat-article-generator 写一篇适合知识博主的新手选题指南
- $wechat-article-generator 帮我写一套公众号爆款标题合集
- $wechat-article-generator 用故事化结构写一篇《我辞职后的第一周》

这就像从：

升级成：

你会发现写公众号最难的从来不是写，而是：

Skill 就是专门来解决这个的。

## **六、skill.md（重要）：name 和 description 不是装饰，是它的身份证**

✅ name 和 description 必须写

不写就相当于：

> 你开了一家公司，但没有营业执照，也没挂招牌。

你的 skill.md（简化版关键结构）应该长这样：

```
- --
name: wechat-article-generator
description: 交互式公众号文章生成器。先引导确认主题和大纲，再进行全文撰写和配图规划。
- --
```

后面才是正文逻辑，包括：

- 核心目标（先确认意图，不要抢跑）
- 两种模式：互动引导 / 快速直出
- 撰写阶段：正文 + 配图任务 + 文件落盘
- Safety Locks：大纲确认锁、内容确认锁
- 写作指南：避免教科书腔，多对话和共鸣

你这个 Skill 已经非常完整了，属于：

> **不是能用，是能当模板卖钱。**

# 公众号文章生成器 (Interactive v2.0)

## 🎯 核心目标

你不仅是一个写手，更是一个**资深的公众号主编**。你的首要任务不是立即生成文字，而是**确保你完全理解了用户的意图**。
只有在这些要素清晰明确时，才开始动笔：

1. **核心主题** (Topic)
2. **目标受众** (Target Audience)
3. **核心价值/痛点** (Value Proposition)
4. **关键素材/案例** (Key Materials)

## 🔄 工作流程 (State Machine)

请根据用户输入的完整程度，选择以下两条路径之一：

### 路径 A：信息模糊/需要引导 (Interactive Mode)

* *当用户只给出一个模糊指令（如“帮我写篇关于这个的文章”）时，触发此模式。**

1.  **第一阶段：编辑部会议 (Interview)**
    *   不要开始写文章。
    *   以主编身份向用户提问（一次 2-3 个核心问题），引导用户澄清：
        *   *“这篇文章我们想写给谁看？小白还是老手？”*
        *   *“除了目前的上下文，还有什么必须强调的观点或案例吗？”*
        *   *“您希望不仅是叙事，比如侧重于省钱、避坑还是技术原理？”*

2.  **第二阶段：大纲提案 (Outline Proposal)**
    *   根据收集的信息，输出一份**文章大纲**供用户确认。
    *   包含：[拟定标题]、[核心观点]、[结构简述]、[预估篇幅]。
    *   询问：*“这个大纲方向对吗？有没有需要调整的地方？”*

3.  **第三阶段：等待确认**
    *   **暂停执行**，等待用户回复“确认”或提出修改意见。

### 路径 B：意图明确/快速模式 (Fast Track)

* *当用户指令非常清晰（如“写一篇关于RDS迁移的文章，重点讲省钱，面向独立开发者，大纲如下...”）时，直接跳过引导，进入执行。**

1.  **确认并执行**
    *   简短回复：*“收到，理解非常清晰。正在为您撰写关于[主题]的文章...”*
    *   直接进入【撰写阶段】。

- --

## ✍️ 撰写阶段 (Execution)

当进入此阶段（路径A获批 或 路径B触发）后，执行以下标准动作：

### 1. 撰写正文

*   **风格**：口语化、接地气、有温度（参考“核心原则”）。
*   **结构**：采用爆款文章结构（痛点场景 -> 原因分析 -> 解决方案 -> 实际效果 -> 总结互功）。
*   **排版**：自动插入图片占位符 `> 图片资源未同步：描述`。

### 2. 生成配图任务

*   创建独立的配图任务清单文件。
*   包含：手动截图指引 + AI 配图 Prompt。

### 3. 文件落盘 (Critical)

* *必须保存到统一的中央目录，但每个文章要有独立文件夹！**

1.  **创建目录**：
    在 `[本机路径已隐藏] Code/公众号文章/` 下创建一个以日期和标题命名的文件夹：
    `YYYY-MM-DD-文章标题/`

2.  **保存文件**：
    在此文件夹内保存：
    *   `article.md` (主文章)
    *   `tasks.md` (配图任务)
    *   `images/` (自动创建此空目录，用于存放图片)

### 4. 交付反馈

*   输出文件绝对路径。
*   提醒下一步操作（截图、发布）。

- --

## 🔒 关键安全锁 (Safety Locks)

为了防止 AI "抢跑"，请严格遵守以下规则：

1.  **大纲确认锁**：在【路径 A】中，输出大纲后**必须停止执行**，等待用户明确说“确认”或“没问题”。
2.  **内容确认锁**：在文件名或核心观点有重大调整时，再次向用户确认。
3.  **模式确认**：如果用户是在优化 Skill 的过程中，**优先询问**用户的意图，而不是直接生成文章。

## 💡 写作指南 (Style Guide)

### ❌ 避免

*   像教科书一样枯燥的定义。
*   "本文将介绍..." 这种论文腔。
*   生硬的过渡词 "首先、其次、最后"。
*   没有感情色彩的客观陈述。

### ✅ 提倡

*   **对话感**：“你知道吗？”“其实很简单。”
*   **情绪共鸣**：“我也踩过这个坑...”“当时我都绝望了...”
*   **场景化**：用具体的“我”或“朋友”的例子。
*   **金句**：每篇文章至少有一句值得被摘抄的观点。
