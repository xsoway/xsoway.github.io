# 除了 Claude Code，我的第二生产力是 omp + DeepSeek V4 Flash：聊聊它和原版 Pi 差在哪

除开 CC 和 Codex，我现在真正的第二生产力是 **orca + omp + DeepSeek V4 Flash**，日常开发基本靠它扛。

平时的套路大概是：方案用订阅的 ChatGPT 出，到了编码阶段就切到这套组合上手写，Codex 随时补位。我的项目没那么复杂，DeepSeek V4.1  Flash 日常用完全够。omp 的 agent + DS V4.1 Flash，用下来就是一对小钢炮。

这话不是拍脑袋。跟上个月在 8 个 Agent Harness 里拿同一个 V4 Flash 跑 30 个高难度任务的结果一致——Pi 那套默认安装过了 20 个，拿了第一，稳妥又便宜。

但这里不打算一味夸工具，想先把两件事讲清楚：**OMP 和它 fork 出来的原版 Pi 到底差在哪**，以及**日常该装哪几个插件**。因为很多人和我一样，一开始根本分不清这俩。

## 先分清：omp 是 Pi 的 fork，但已经不是一个量级的东西

Pi 是 Mario Zechner 在 2025 年 8 月做的编码代理，纯 TypeScript。omp（oh-my-pi）是 Can Bölük 从 Pi fork 出来的独立项目，两个项目各自发展，omp 会定期从上游合并 Pi 的改动。

名字像，血缘近，但规模差得离谱：

| | Pi | omp |
| --- | --- | --- |
| 规模 | 约 20 万行 TypeScript，没 Rust | 约 112 万行 TS + 17 万行 Rust |
| 包结构 | 4 个包 | 16 个包 + 8 个 Rust crate |
| commit | 4,600+ | 14,000+ |
| coding-agent（CLI 包） | 104K | 631K |

差距最大的就是 `coding-agent` 这个核心。Pi 那边是 agent 的基础流程（会话、工具调度、RPC 模式），omp 在这之上加了一整套东西。一句话概括能从 README 借来：**想要开箱即用，选 omp；喜欢极简自己折腾，选 pi。**

## omp 多出来的，都是 Pi 刻意没做的正餐

很多人用 Pi 的第一反应是"太素了"：内置工具常年就 7 个（跑命令、读写文件、编辑、搜代码），没有 plan mode，不集成 MCP，连权限弹窗都嫌多余。这其实是 Pi 的哲学——作者对内核有洁癖，能力靠扩展自己长出来。

omp 反过来，把这些补成了出厂标配。挑几个日常真能用上的：

**Hashline 和 AST 编辑**。AI 改代码一直是"把旧代码原样抄一遍再交差"，抄错一个空格就匹配不上，重试十几轮。Hashline 用 tree-sitter 把代码按语法块算哈希当锚点，AI 只要说"把标识 a3f2 那段换了"就行，不用抄。AST 编辑则是按语法结构批量改，比如把一堆 `console.log` 换成 `logger.info`，先预览、再原子写入，不会改到一半卡死。

**LSP 集成**。omp 内嵌了语言服务器客户端。重命名一个函数，不光是改定义那一处，`index.ts` 的 barrel export 和别名导入里的引用会一起更新。这活儿靠纯文本匹配基本干不了。

**DAP 调试器**。C++ 崩了 attach lldb 打断点看变量，Go 卡住了 attach dlv 遍历 goroutine，Python 挂了 attach debugpy 执行表达式。AI 不是看源码猜 bug，是能真跑程序看运行时状态。

**子代理**。Pi 也有子代理，但 omp 多出三样：git worktree 隔离（各自改各自的目录不冲突）、子代理间 IRC 通信（A 改函数签名通知 B 改调用处）、结构化输出（返回 schema 校验过的字段，不用从散文里解析）。

**Advisor 双模型**。同一个会话配两个模型，一个写一个审。审的每一轮读主力操作，发现问题注入提醒甚至硬性阻止，跑在独立上下文里，不跟主力抢 token。这个对价格敏感、想省钱又怕翻车的场景很实用。

**Hindsight 跨会话记忆**。聊完就忘是全行业通病。omp 用 `retain` / `recall` / `reflect` 三件套，会话结束自动压缩要点到项目记忆库，下次开新会话第一轮就"记得上次聊过 API 主路由是 /v2/orders"。按项目隔离，A 项目学的不会串到 B。

所以"pi 还是 omp"这个选择题，本质是**要简到家，还是要把能力装齐**。爱折腾、享受自己攒配置的用 Pi；想拿来就能干活、少碰配置多的，omp 省心得多。

## 同一套箱子，能不能装别人——关键在 Harness 而非模型

上个月 Composio 做了个公开测试，值得记住：同一个 DeepSeek V4 Flash，分别放进 8 种 Harness，跑 30 项高难度任务。结果是：

- **Pi：20/30，66.7%**，第一
- **Oh My Pi：17**，第二
- Claude Code、Codex、Deep Agents：16
- Prime、Hermes：15
- OpenCode：14，垫底

同一个模型，只换外面的底座，成功率能从 46.7% 拉到 66.7%，差整整 20 个百分点。成本差距更离谱：Pi 平均一项成功任务花 0.028 美元，Claude Code 要 0.195，将近 7 倍。中位耗时上 Pi 的 132.2 秒略慢于 CC 的 122.7 秒，但综合成功率、速度和成本，它在这轮测试里最突出。

更有意思的是，Pi 用的是**全新、没调过参数的默认安装**，只接了测试要用的 MCP 插件。反而是会话量最庞大的 Prime（有的会话吃到 350 万 token、33 次工具调用），把评分器都跑超时了，6 次运行没被计入成绩。**功能装得越多，越容易被自身的运行负担拖慢**。

Pi 拿第一还有个技术底子：DeepSeek 的缓存是按提示词前缀命中的，基线越稳定命中率越高。Pi 那套"稳定环境摘要、固定温度、确定性摘要哈希"的设计，能把手动配置的缓存命中率做到 99% 以上。开发者 0xEvan 用 Pi 调 V4 Flash 处理了快 10 亿输入 token，缓存命中 99.93%，只花了 2.65 美元；不命中按常规价要 132 美元。

当然这不是说"轻量适用于所有人"。这套组合更适合**任务相对短程、可控、对成本敏感、自己愿意调一点**的场景。长链条、多分支、深依赖上下文的活，极简 Harness 可能丢必要的中间层。

## 插件：日常四件套起步，剩下的按需加

我的原则和来源社区里的共识一样：**插件不是越多越好，各司其职，装之前先想清楚这活是 Pi 天生该干的，还是我的习惯需要**。起步先装这四个，跑几个仓库再决定留不留：

- **pi-web-access**：给 Pi 补联网——网页搜索、抓取、GitHub 仓库克隆、PDF 解析、YouTube 理解。零配置可用。
- **pi-subagents**：派生子代理并行干活，内置 scout / researcher / reviewer / oracle 角色。大改动跑完派个只读子代理挑刺，比自查自纠靠谱。
- **pi-fff**：预索引文件，用模糊匹配 + frecency + Git status 加速大仓库搜索。代码库大了不卡。
- **pi-context-view**：估算当前会话上下文占用，防止悄悄塞满。配一个底部状态栏提醒水位，过了半就主动压缩或开新会话。

往里加的话，按我自己实际留下的清单：

| 插件 | 用途 |
| --- | --- |
| @narumitw/pi-plan-mode | 规划模式，锁死写权限，逼我先想清楚再动手 |
| pi-memory | 记忆存成 markdown 文件，跨会话不忘事，随时能改能查 |
| pi-mcp-adapter | 一个代理工具接整个 MCP 生态，按需发现、懒启动，只占约 200 token |
| pi-cache-optimizer | 稳定提示词前置、动态内容后置，提高 DeepSeek 缓存命中率，长期省钱 |
| @narumitw/pi-btw | 旁路提问，干到一半插问也不打断主线 |
| @narumitw/pi-file-context | 圈精确文件行喂上下文，大文件不整份刷屏 |
| pi-open-tui | 精致皮肤，底部状态栏显示模型、分支、上下文、token、成本 |

几个安装相关的坑：插件大多发 npm，命名习惯 `pi-<name>`，装一个 `pi install npm:pi-open-tui`。想先试再决定，用 `-e` 跑一个会话不实际安装：`pi -e npm:pi-memory`。清单存在 `~/.pi/agent/settings.json` 的 `packages` 数组，一目了然也能手工改。配 DeepSeek 用 `DEEPSEEK_API_KEY` 环境变量就行，Pi 从 0.70.1 起内置了 V4 Flash，`pi --provider deepseek --model deepseek-v4-flash` 一条命令起来，模型目录里直接选。

## 感想

回到开头那句话。给你我的判断：**不在乎配置仪式感、就想拿起来能干活的，直接上 omp + V4 Flash，插件按"联网 + 子代理 + 上下文 + 缓存"这四件补齐**；愿意享受极简、享受一点点组装过程的，原版 Pi + 插件也完全成立，只是要知道自己想要的那部分能力多半要自己装。

不管走哪条，深水区那句话没变：**这个时代，真正决定上限的不是模型，是它外面的那层 Harness**。同样一个箱子，会不会用、会不会调，差距能拉到 20 个百分点——这才是值得花时间的地方。
