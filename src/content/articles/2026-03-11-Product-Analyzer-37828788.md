# Product Analyzer

## Overview

提供全面的产品分析框架和工具，支持从战略层到执行层的多维度产品评估，包括用户画像分析、功能结构分析、竞品对比、用户体验评估、商业模式分析等，输出结构化的产品分析报告和可执行的改进建议。

## 使用场景

当出现以下场景时使用此技能：
- 新产品规划和设计前的市场分析
- 现有产品的全面诊断和优化建议
- 竞品研究和差异化策略制定
- 产品迭代决策支持
- 用户体验问题诊断和改进方案
- 商业模式设计和验证
- 产品定位和市场策略制定

## 分析流程

### 阶段 1：信息收集

在开始分析前，向用户收集以下信息：

* *必需信息：**
- 产品名称和类型（移动应用/网页应用/SaaS/硬件/服务）
- 产品核心功能和定位
- 分析目标（竞品分析/产品优化/新产品设计等）

* *可选信息：**
- 目标用户描述
- 主要竞争对手
- 用户反馈或数据
- 商业目标
- 分析深度要求（高层概览/详细分析）

如果用户提供的信息不完整，基于已有信息进行分析，并明确说明假设和限制。

### 阶段 2：选择分析框架

根据分析目标选择合适的分析框架组合：

* *战略分析：** SWOT 分析 + PEST 分析
* *需求优先级：** Kano 模型
* *用户体验：** 用户旅程地图 + HEUR 评估
* *竞品研究：** 竞品分析矩阵 + SWOT
* *商业模式：** 商业模式画布

框架详细说明参考 `references/analysis_frameworks.md`

### 阶段 3：执行多维度分析

对产品进行以下维度的系统分析：

#### 3.1 产品概述
- 产品定位和核心价值
- 目标市场和市场背景
- 产品目标和愿景

#### 3.2 用户分析
- 构建用户画像（年龄、性别、职业、收入、教育等）
- 分析用户需求（核心需求、次要需求、潜在需求）
- 绘制用户旅程地图（意识 → 考虑 → 获取 → 使用 → 忠诚）
- 识别用户痛点和障碍

#### 3.3 功能分析
- 列出核心功能模块
- 评估功能完整性和可用性
- 使用 Kano 模型对功能需求分类（基本型/期望型/兴奋型/无差异型/反向型）
- 识别缺失功能和待优化功能

#### 3.4 竞品分析
- 识别主要竞争对手
- 构建竞品分析矩阵（功能、价格、用户体验、市场份额等对比）
- 分析竞品的优势和劣势
- 制定差异化策略

#### 3.5 SWOT 分析
- 优势 (Strengths)：内部优势、核心能力、独特价值主张
- 劣势 (Weaknesses)：内部不足、待改进点、资源限制
- 机会 (Opportunities)：市场机会、增长空间、新技术趋势
- 威胁 (Threats)：竞争压力、市场风险、政策法规变化
- 制定 SO/ST/WO/WT 战略矩阵

#### 3.6 用户体验评估
- 分析关键交互流程
- 使用 HEUR 10 条启发式原则评估可用性
- 识别界面设计和可用性问题
- 评估用户满意度

#### 3.7 商业模式分析
- 绘制商业模式画布（9 个模块）
- 分析盈利模式和定价策略
- 评估市场潜力（市场规模、增长趋势、竞争格局）
- 计算关键指标（ARPU、LTV、CAC）

### 阶段 4：综合评估和问题识别

* *问题优先级排序：**
- 🔴 高优先级：影响核心价值或用户体验的关键问题
- 🟡 中优先级：影响产品体验的次要问题
- 🟢 低优先级：优化性问题

* *识别改进机会：**
- 评估每个机会的预期收益
- 评估实施难度
- 建议优先级

* *风险评估：**
- 市场风险、技术风险、运营风险、竞争风险
- 评估可能性和影响程度
- 制定应对策略

### 阶段 5：生成可执行建议

按时间维度提供具体建议：

* *短期建议（1-3 个月）：**
- 立即可执行的优化项
- 低成本高收益的改进
- 紧急问题的修复方案

* *中期建议（3-6 个月）：**
- 功能迭代计划
- 用户体验提升
- 市场策略调整

* *长期建议（6 个月以上）：**
- 产品战略方向
- 技术架构演进
- 市场扩张计划

每个建议包括：
- 具体行动项
- 实施原因和预期效果
- 资源需求估算

### 阶段 6：输出分析报告

使用 `references/report_template.md` 中的模板，生成结构化的产品分析报告。

* *报告结构：**
1. 执行摘要（核心发现、关键建议、整体评价）
2. 产品概述（定位、市场背景、目标）
3. 用户分析（画像、需求、旅程地图）
4. 功能分析（结构、评估、Kano 分类）
5. 竞品分析（矩阵、详细对比、差异化策略）
6. SWOT 分析（优势、劣势、机会、威胁、战略矩阵）
7. 用户体验评估（流程、HEUR 评估、满意度）
8. 商业模式分析（画布、盈利模式、市场潜力）
9. 问题与机会（关键问题、改进机会、风险因素）
10. 建议（短期、中期、长期）
11. 结论（总体评价、战略建议、下一步行动）
12. 附录（数据来源、参考资料、分析方法）

### 阶段 7：迭代优化

* *反馈循环：**
1. 提交初步分析报告
2. 收集用户反馈和补充信息
3. 针对特定维度深入分析
4. 优化建议和结论
5. 生成最终版本

## 输出要求

### 报告格式
- 使用 Markdown 格式
- 包含清晰的标题层级
- 使用表格进行对比和评分
- 使用图标增强可读性（✅❌⭐🔴🟡🟢）

### 内容质量
- **深度：** 分析要有深度，避免表面化
- **准确性：** 基于事实和逻辑推断
- **可执行性：** 建议要具体、可操作
- **数据支撑：** 关键结论要有数据或分析支撑
- **逻辑清晰：** 论证要有清晰的逻辑链条

### 报告长度
- 高层概览分析：2000-3000 字
- 详细分析报告：5000-10000 字
- 深度分析（包含竞品）：10000 字以上

根据用户需求调整报告深度和长度。

## 使用技巧

### 1. 渐进式分析
- 从高层概览开始，识别关键问题
- 根据用户反馈深入特定维度
- 避免一次性输出过多信息

### 2. 交互式分析
- 在分析过程中主动询问关键信息
- 基于用户反馈调整分析重点
- 迭代优化分析结果

### 3. 视觉化呈现
- 使用表格对比竞品
- 使用图标标记优先级
- 使用结构化列表组织信息

### 4. 行动导向
- 每个问题都要有解决方案
- 每个建议都要有预期效果
- 每个机会都要有优先级

## 约束条件

### 分析范围
- 时间范围：默认分析当前产品状态，除非用户指定历史对比
- 地理范围：默认全球或用户指定市场
- 数据来源：基于公开信息、用户提供信息、行业常识

### 分析假设
- 如果缺少关键数据，明确说明假设
- 区分事实推断和假设
- 提醒用户验证关键假设

### 质量保证
- 使用多个分析框架交叉验证结论
- 识别和说明分析局限性
- 建议用户收集更多数据验证关键发现
