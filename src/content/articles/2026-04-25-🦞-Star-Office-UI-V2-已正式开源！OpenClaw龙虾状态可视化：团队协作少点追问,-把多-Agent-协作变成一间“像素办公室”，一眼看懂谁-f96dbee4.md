# 🦞 Star Office UI V2 已正式开源！OpenClaw/龙虾状态可视化：团队协作少点追问, 把多 Agent 协作变成一间“像素办公室”，一眼看懂谁在干活

多 Agent 协作最常见的问题不是“跑不起来”，而是“看不清”。

同一时间可能有多个智能体在写代码、查资料、跑命令、同步进度；消息在不同频道里刷，最后只剩两种结局：要么靠猜，要么靠追问。

Star Office UI 的思路很直接：把这些状态做成一个实时像素办公室看板——状态变化对应角色在办公室里移动（工作区/休息区/bug 区），再配一张“昨日小记”，让团队随时知道：谁在线、谁在干什么、昨天干了什么。

项目地址：<https://github.com/ringhyacinth/Star-Office-UI>

- --

## 它解决的到底是什么问题

从 README 的描述看，这个项目本质是在补“协作可视化”这一块：当智能体数量一多，协作就会变成一个典型的工程问题——状态必须可观测、进度必须可追踪、异常必须可暴露。否则所有“自动化”都会退化成“到处找人问”。

Star Office UI 把这件事做成了一个更轻量、也更团队友好的形态：看板不讲大道理，只回答三个问题：谁在干活？正在干啥？有没有卡住？

- --

## 核心能力：状态可视化 + 昨日小记

目前实现的能力可以概括成两层。第一层是状态可视化：支持 `idle`、`writing`、`researching`、`executing`、`syncing`、`error` 等状态，并把它们映射到办公室里的不同区域，通过动画和气泡展示。

第二层是“昨日小记”：后端从 `memory/*.md` 读取昨天（或最近可用）的记录，做基础脱敏后在前端展示成卡片。对团队来说，这相当于一个低成本的“复盘痕迹”，不用翻聊天记录，也能知道昨天发生了什么。

此外还有几件很实用的工程化细节：支持手机端访问；中英日三语切换；资产可替换（角色/场景素材可自定义）；支持邀请访客加入（通过 join key 推送状态）。

## 这个项目实现了什么

Star Office UI 目前实现了：

1. **可视化龙虾工作状态**
   - 状态：`idle`（闲置）、`writing`（工作）、`researching`（研究）、`executing`（执行）、`syncing`（同步）、`error`（报 bug）
   - 状态会映射到办公室里的不同区域，并通过动画/气泡展示。
2. **“昨日小记”微型总结**
   - 前端展示“昨日小记”卡片。
   - 后端从 `memory/*.md` 中读取昨天（或最近可用）的记录，做基础脱敏后展示。
3. **支持邀请其他访客加入办公室（功能持续迭代中）**
   - 通过 join key 加入。
   - 访客可持续 push 自己状态到办公室看板。
   - 当前已可用，但整体仍在持续优化交互与接入体验。
4. **已适配手机端访问**
   - 移动端可直接打开与查看状态（适合外出时快速查看）。
5. **支持中英日三语切换**
   - 已支持 CN / EN / JP 三语切换。
   - 语言切换会实时作用于界面文案、加载提示与角色气泡。
6. **支持自定义美术资产**
   - 支持在资产侧边栏替换角色/场景素材。
   - 支持动态素材重切帧与参数同步（frame size / frame range）以避免闪烁。
7. **支持接入自己的生图 API（可无限换背景）**
   - 支持接入自有生图 API 进行“搬新家/找中介”式背景更新。
   - 推荐模型：`nanobanana-pro` 或 `nanobanana-2`（结构保持更稳定）。
   - 基础看板功能不依赖 API；不接入 API 也可正常使用核心状态看板与资产管理。
8. **公网访问方式灵活**
   - Skill 默认建议使用 Cloudflare Tunnel 快速公网化。
   - 也可以使用你自己的公网域名 / 反向代理方案。

## 30 秒跑起来（本地）

README 给的路径比较直白：克隆仓库、装依赖、复制一份状态文件，然后起后端。关键命令如下：

```bash
# 1) 下载仓库
git clone https://github.com/ringhyacinth/Star-Office-UI.git
cd Star-Office-UI

# 2) 安装依赖
python3 -m pip install -r backend/requirements.txt

# 3) 准备状态文件（首次）
cp state.sample.json state.json

# 4) 启动后端
cd backend
python3 app.py
```

启动后打开：`http://127.0.0.1:18791`。

然后可以用脚本快速切状态（在项目根目录执行）：

```bash
python3 set_state.py writing "正在整理文档"
python3 set_state.py syncing "同步进度中"
python3 set_state.py error "发现问题，排查中"
python3 set_state.py idle "待命中"
```

## 2026-03 重制版的变化：更像一个可长期维护的产品

README 里把这次重制的改动点写得很清楚：不仅是 UI 翻新，而是围绕“可维护”和“可扩展”做了一次系统性升级。重点变化包括：三语化（CN/EN/JP）、资产管理（用户可自定义全量美术资产）、接入生图 API（房间装修/换背景）、美术资产替换与切帧逻辑优化（减少错帧/缓存干扰）。

其中最工程化的一点是“资产命名与索引映射的重建”，这类工作看起来不炫，但决定了后续能不能持续迭代而不崩。

## 适合什么团队/什么阶段

适合的场景很明确：团队已经开始用多个 agent，但状态散落在各处，需要一个统一的“观测面板”；或者个人把 OpenClaw/龙虾当日常助手用，希望一眼看出它到底在忙还是在卡。

从工程管理角度看，它更像一个“轻量可观测性组件”：不是为了管人，而是为了减少追问、减少误解、减少无效同步。
