很多人第一次见到 neofetch，不是在教程里，而是在别人晒的终端截图里：开机后命令行顶部整整齐齐排着一块“信息卡”，左边是发行版 Logo，右边是系统、内核、运行时间、CPU、内存……像一张系统体检表贴在屏幕上。

这套玩法流行了很多年，但有一个问题：原作者早就不维护了。2024 年 4 月 26 日，neofetch 的作者 dylanaraps 把仓库归档成了只读状态——代码还在，但没人再往里加功能。

于是接棒者出现了：**Fastfetch**。

## 它是什么

一句话：一个在终端里显示系统信息的命令行工具，长得像 neofetch，但用 C 语言从头实现，主打性能和可定制。

GitHub 上 2.5 万 + 星，MIT 协议，完全免费。你安装后敲一个 `fastfetch`，屏幕上就会以 Logo + 信息列表的形式，把操作系统、内核版本、CPU、GPU、内存、磁盘占用、运行时长等一次显示出来。

它不是我编的“新版 neofetch”——就是照着 neofetch 的定位做的。官方仓库 README 第一句就写得很直白：一个“neofetch-like”的系统信息工具。

## 为什么需要重做一个

neofetch 本身是个好工具，但它停更了。不是作者偷懒，是典型的“开源项目断档”：维护者把仓库归档成只读，意味着即便你发现 bug、有更好的想法，官方也不会合入。

而系统信息这种工具，恰恰依赖持续维护——新的硬件、新的内核、新的渲染协议（比如 Wayland）在不停冒出来，没人更新就会慢慢失真。fastfetch 的 FAQ 里专门点过一句：neofetch 从来没真正支持过 Wayland 协议。

所以 fastfetch 的第一卖点是“活着的”：仓库还在持续更新，最近一年有约 1400 次提交，最新版本号已经推到 2.71。

## 它快在哪

名字就带“fast”。要理解它为什么快，得先知道 neofetch 的老办法：**它是用 bash 写的**，也就是一行一行顺序执行 shell 命令，挨个去读系统信息。

fastfetch 换了路子——**用 C 语言实现**，很多信息是直接调系统接口拿的，而不是派生一堆 shell 子进程。信息收集还做了并发处理。

一个直观的对比是它打印数字的精度：同样的内存占用，老工具的脚本逻辑会显示成 `555 MiB`，fastfetch 显示 `555.00 MiB`；磁盘 `23 G` 显示成 `22.97 GiB`。前者是脚本做了简化，后者是它读到的真实值。

一个常见的用法：把它设为 shell 启动时自动运行，一开终端就先扫一眼这台机器的状态，省得每次手动敲 `ip addr` 一类的命令查。

## 可定制到什么程度

很多工具“可定制”只是嘴上说说，fastfetch 是认真的。

它用 **JSONC**（带注释的 JSON）做配置。想了解有哪些模块可调，跑一条 `fastfetch -c all.jsonc`，几乎所有支持的模块都会列出来，你看着挑。想知道某项具体数据，可以 `fastfetch -s <模块名> --format json` 只看那一块。还能用官方在线的配置生成器，在网页上点选，导出配置。

Logo 也是可以换的，不只是系统的默认图。它内置了各发行版的 ASCII 图案，也支持自定义图形。

## 常用命令速查

- `fastfetch`：默认配置跑一次，显示信息卡。
- `fastfetch -c all.jsonc`：列出所有支持的模块，用来发现能显示什么。
- `fastfetch -s <模块名>`：只查某一个模块，比如 `fastfetch -s cpu`。
- `fastfetch -s <模块1>:<模块2> --format json`：以 JSON 格式输出指定模块的数据，方便脚本调用。
- `fastfetch --help`：查看全部参数。
- `fastfetch --gen-config [</路径>]`：生成一份最小配置，作为定制的起点。
- `fastfetch -c <文件名>`：加载某个预设或自定义配置。

## 你得知道的几个边界

别因为它免费好用就放松警惕，有几个点直接影响你用不用、怎么用：

**1. 支持范围分两档。** 它声称支持 Linux、macOS、Windows 8.1+、Android、FreeBSD、多个 BSD 变体、Haiku、Solaris。但官方在 README 里明说：**只在 x86-64 和 aarch64 两种架构上积极测试**，其他平台“能用但不保证”。你在冷门架构上跑，出问题别惊讶。

**2. 有个高风险模块。** fastfetch 带一个 `Command` 模块，可以执行任意 shell 命令——这正是“自定义乐园”的阴暗面。官方自己也给了警告：如果你复制了一份来路不明的配置，里面可能藏了恶意命令。

这提醒了一条使用原则：**别随便 `curl | 运行` 或粘贴陌生配置文件**，用之前先打开看一眼内容。

**3. 默认只开少量模块。** 装上跑 `fastfetch`，看到的只是它能力的冰山一角，多数功能默认是关的。想发现全部，得用 `-c all`。

## 它适合谁

- **普通用户**：如果只是想要一块好看的终端信息卡片，装上用默认配置就够了，30 秒搞定。
- **爱折腾的开发者**：想研究一个系统信息工具怎么做到快、怎么组织几十个检测模块，源码是现成的 C 教材，仓库里 `src/detection` 下挂了 60 多个检测模块。
- **想做测试的你**：这类“读系统状态”的工具，天然适合写脚本校验——不同架构、不同系统版本下，读到的 CPU/内存/磁盘数据准不准、速度快不快，都可以做成回归用例。

## 一个较真的地方

在系统工具这个品类里，很少看到“读信息”能当成一门严肃工程来做。fastfetch 不满足于“能显示”，它在较真：数字准不准、快不快、能不能按需只查一块、配置好不好写。

这种态度，恰恰是 neofetch 退场后社区需要的——继任者不只是抄了个壳，而是把“显示系统信息”这件事，重新实现了一遍。

如果你想试试，从官方仓库的 Release 页下载对应平台的包即可。想自己编译，仓库根目录有 `run.sh` 和标准 CMake 构建流程。
