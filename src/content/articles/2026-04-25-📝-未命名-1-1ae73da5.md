二、目标配置口径 这次优化的目标我建议定成：

1. Telegram 上更安静
    
2. 更像交付型技术助理
    
3. 编码任务更稳
    
4. 子 Agent 更快更省
    
5. 主模型挂了也能兜底
    
6. 简单问题成本更低
    
7. 与你当前 OpenClaw + Obsidian 共享工作区方案兼容
    

三、推荐方案 我给你分成“必改项 / 建议项 / 可选收缩项”。

A. 必改项 这些是收益最高、风险最低的。

1. Telegram 输出降噪 现在：
    

- display.tool_progress: all
    
- display.tool_progress_command: false
    

建议改成：

- display.tool_progress: new
    
- display.tool_progress_command: true
    

效果：

- 平时 Telegram 不刷屏
    
- 需要时你还能手动开详细过程
    

2. 助手人格收敛 现在：
    

- display.personality: kawaii
    

建议改成：

- concise
    

备选：

- technical
    

我的建议： 先用 concise。 因为你要的是“像交付，不像聊天”。

3. 补时区 现在：
    

- timezone: ''
    

建议改成：

- Asia/Shanghai
    

效果：

- cron
    
- 时间表达
    
- 周期任务
    
- 日报类任务 都会更稳
    

4. 子 Agent 分层 现在：
    

- delegation.provider/model 为空
    

建议：

- delegation.provider: openrouter
    
- delegation.model: google/gemini-2.5-flash
    

效果：

- 主 Agent 继续负责统筹
    
- 子 Agent 专门跑轻分析 / 检查 / 资料整理 / 扫描任务
    
- 成本和速度都会更好
    

B. 建议项 这些也很值，但比必改项稍微多一点外部依赖。

5. 增加 fallback_model 建议： fallback_model: provider: openrouter model: anthropic/claude-sonnet-4
    

作用：

- 主模型限流、失败、503、429 时自动切换
    
- 对 Telegram 在线助理特别值
    

前提：

- 你要确认 OpenRouter key 已经就绪
    
- 或者你想改成别的 fallback provider
    

6. 开 smart_model_routing 建议： smart_model_routing: enabled: true max_simple_chars: 160 max_simple_words: 28 cheap_model: provider: openrouter model: google/gemini-2.5-flash
    

作用：

- 简单短问题走便宜模型
    
- 复杂任务继续用主模型
    
- 降本明显
    

C. 可选收缩项 这部分是“技术工作台化”，不是必须立刻改。

7. 收缩非核心 toolsets 当前启用：
    

- image_gen
    
- tts
    
- homeassistant
    

如果目标是“Telegram + 编码专用版”，我建议可考虑关闭：

- image_gen
    
- tts
    
- homeassistant
    

保留核心：

- web
    
- browser
    
- terminal
    
- file
    
- code_execution
    
- vision
    
- skills
    
- todo
    
- memory
    
- session_search
    
- delegation
    
- cronjob
    
- clarify
    

好处：

- 更聚焦
    
- 更少干扰
    
- 更像技术专用机
    

风险：

- 你以后如果突然想让 Hermes 直接发语音/生成图/控家居，就得再开回来
