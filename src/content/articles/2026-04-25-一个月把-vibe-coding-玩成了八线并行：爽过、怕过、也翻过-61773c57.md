# 一个月把 vibe-coding 玩成了八线并行：爽过、怕过、也翻过

## 
这个月其实是在做同一件事：把一堆“看起来很酷”的工具和流程，真拿来用之后到底会发生什么。因为 AI、Agent、自动化这些东西突然就挤到日常里，谁都绕不开。真正想劝的是别被“完美流程”绑死，要能随时切换方案，才能活下来。

## 
30天、一个普通工程狗、把提示词调教、封面自动化、发版巡检、代理折腾、身体恢复、歌单整理，全塞进同一份月度清单里，结果居然还都“done”了。

说白了就是：我在用一堆新玩意儿把工作流程重新装了一遍，然后不停地回滚、修补、再试。

- --

## 模块 3｜离谱案例轰炸（好笑 → 精明 → 越界）

先说最“好笑”的，25 年终总结 done。听起来像一句废话，但我当时是真的觉得“终于还了债”，那种感觉像欠了一年的房租突然还清了，爽得我差点想发朋友圈。真他妈爽。

接着是 article-prompt 调教了 N 轮也算 done。用的是 **skill 方式编写**，这事儿我一开始还挺自信，结果一进深水区就发现自己像揉面：规则要一条条揉进去，太干了不行，太湿了也不行，得“精打细磨”。调教过程中学到的经验就是：跟 AI 交流像跟人说话，但得更明确，prompt 里的每条规则都要反复打磨，过程真的就是一撮再撮。我当时没绷住，觉得自己像在厨房反复补盐。狗东西，真费劲。

封面图制作及上传自动化 done。看到大神用 prompt 生成 HTML 卡片的例子，我当场就“嗯，有搞头”。思路就是：描述你想要的风格 → 文字图片分离 → 生成 HTML → 用 playright 截图 → 再推送上传。这个流程像拍证件照：先化妆、再摆姿势、最后机器咔嚓。一步错就像证件照把你头砍掉。真他妈刺激。

* *封面自动化步骤（≥6 步）**

1. 明确你想要的封面风格（我当时用“卡片式”）
2. 把文字内容和图片素材拆开，别糊一起
3. 用 prompt 生成 HTML 结构
4. 把 HTML 渲染成浏览器页面
5. 用 playright 进行截图
6. 把截图产物推送上传
7. 做一次肉眼复查（不然翻车更快）

我本来想把这段放后面，但写到这儿突然觉得它其实是核心流程，先放了。

再来是发版检测质量（前后端及服务器部署）done。最开始我想把脚本部署到生产服务器，还打算塞进 pipeline 流程里强制执行。结果两记闷棍：服务器系统版本太久，依赖包装不上；巡检脚本又要调用大模型，过程慢得像水电费狂跳，硬塞进 pipeline 会直接拖慢各项目发版。那个瞬间我真他妈后背发凉——想象一下你按下发布按钮，结果它卡在“AI 正在思考”，那感觉像在高速路上突然遇到路障。

纠结很久，我换了个办法：既然还是实验阶段，就没必要死绑定。索性写了个前端页面，每次发版前拿到 git 地址，直接拉取到本地进行巡检并生成报告作为参考。这样既让巡检独立、不和发版冲突，又能灵活控制 😁。这就像体检：你可以去医院排队（pipeline），也可以自己先在家量个体温（本地巡检）。我当时还觉得自己挺聪明，后来再看，这其实是绕开僵硬流程的自救。

接着是 opencode + oh my opencode 的搭建折腾，done。VPN 一定要开启 **TUN 模式**，走虚拟网卡代理，这个点像给家里换了总闸，没开就全屋断电。顺手还研究了下 [研究了下skill.md](http://研究了下skill.md) & [agents.md](http://agents.md) 的作用和用途。opencode-desktop 桌面版挺不错，最近一直版本更新，希望越来越好。说实话，频繁更新像天天收到装修师傅敲门，一边烦一边又有点期待。

然后是 antigravity 登录问题。这个东西真的需要运气和玄学，我最后直接放弃了：使用 TUN 方式无解、换代理工具无解、换账号/换区域也无解。它像抽奖机，投币无数，连个灯都不亮。我当时判断错了，以为“换个姿势就能登上”，结果现实直接扇脸。

我现在也不确定是不是我运气差，还是这玩意儿本来就这样。

唉。  
就这样。  
真的。

最后是身体这条线：眼睛散瞳后，最后一周恢复算是完全恢复，开始减肚计划。只早上吃点，中午和晚饭不吃。也许是最近工作忙，竟把饿这件事给忘了，反倒更容易坚持 😄。坚持三天一过，真的有些许变化：肚子软了，也不是那么想乱吃东西，对重口味更不一点不想，整个人也觉得轻松很多，心内心外都轻盈了、不混浊。希望坚持下去——不是不吃，是少吃，轻淡为主，加油。这个过程像给系统降载，先把噪音关掉，才知道原来机器还能跑这么顺。

### 发版巡检两条路的对比（我当时纠结的根源）
| 方案                        | 好处                 | 卡点                       |
| --------------------------- | -------------------- | -------------------------- |
| 脚本上生产服务器 + pipeline | 流程统一、强制执行   | 系统版本太旧、依赖包装不上 |
| 本地拉取 git + 前端页面巡检 | 独立灵活、不影响发版 | 需要人工触发、仍在实验阶段 |

## 代码块（工程真实感）

```bash
# 使用场景：发版前本地巡检，不影响 pipeline
# 输入示例：GIT_URL="https://example.com/repo.git"
# 可运行代码：
GIT_URL="https://example.com/repo.git"
git clone "$GIT_URL" repo && cd repo
bash ./inspection.sh
# 预期输出：生成一份本地巡检报告（比如 report.html）
# 翻车点提醒：脚本调用大模型会慢到超时，像发版卡在高速入口，团队直接炸锅
```

```bash
# 使用场景：封面图自动化，HTML 卡片 + playright 截图
# 输入示例：STYLE="卡片式极简"
# 可运行代码：
STYLE="卡片式极简"
HTML="card.html"
node render-card.js "$STYLE" > "$HTML"
npx playright screenshot "$HTML" cover.png
# 预期输出：cover.png 生成并可上传
# 翻车点提醒：截图分辨率错了会糊成马赛克，像证件照被裁到只剩半张脸
```

```python
# 使用场景：prompt 规则精打细磨，反复调教
# 输入示例：rules = ["必须分步骤", "禁用空洞结论", "保持口语感"]
# 可运行代码：
rules = ["必须分步骤", "禁用空洞结论", "保持口语感"]
for i, rule in enumerate(rules, 1):
    print(f"{i}. {rule}")
# 预期输出：
# 1. 必须分步骤
# 2. 禁用空洞结论
# 3. 保持口语感
# 翻车点提醒：规则太多会让模型“卡壳”，像给新人塞了100条军规，直接懵圈
```
