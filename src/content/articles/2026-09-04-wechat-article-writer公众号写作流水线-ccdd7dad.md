# 公众号文章全流程管家：wechat-article-writer 怎么把「选题到发布」串成一条流水线

`wechat-article-writer` 是一个面向 AI Agent 的公众号文章全流程写作 Skill，负责把「从选题到发布就绪」的整条链路固化进一套可执行流程。它不是一个能直接调用的文章接口，而是一份给 Claude Code 这类 Agent 的编排指令：触发后，Agent 按固定八步把一篇公众号内容从头到尾生产出来，连标题备选、转发话术、朋友圈文案、封面图和发布前核对清单一起交付。仓库以 MIT 协议开源。

一句话讲透它的价值主张：通用做法是「让 AI 写一篇文章」，这个 Skill 做的是「让 AI 生产一篇公众号内容」，后者把排版、封面、话术、发布前置检查这些本来要人手动接的环节都并进了同一条流水线。下文按主线拆开它做了什么、每一步为什么存在，并走一遍完整案例。

## 一、它不是"写文章工具"，是一份"内容生产流程编排"

把这个 Skill 看成一本书的目录，比看成一个 API 更准确。它真正沉淀的是一整套做公众号的方法论：

- 一篇内容出厂需要哪些环节；
- 每个环节要喂什么输入、要给什么输出；
- 哪一步最容易因为「想当然」而翻车，所以要主动确认；
- 哪些内容类型在平台审核里必踩，所以要先审查后动手。

仓库结构也印证了这个判断：主指令 `SKILL.md` 定义流程，`resources/` 下放了 5 个不同文体的骨架（playbook），`references/` 里放了安全案例回顾、封面图工作流、内容追踪表等配套资料。它是一个「流程 + 模板 + 规范」的集合。

## 二、八步主链路：从触发到发布就绪

这个 Skill 把公众号内容生产拆成八个阶段，无论长文还是短评都走同一套主链路。

```mermaid
flowchart LR
    A[触发词] --> B[STEP0 内容安全审查]
    B --> C[STEP1 确认写文参数]
    C --> D[STEP2 匹配内容骨架]
    D --> E[STEP3 采集素材 写正文]
    E --> F[STEP4 生成内容包]
    F --> G[STEP4.5 生成封面图]
    G --> H[STEP5 md.doocs.org 排版]
    H --> I[STEP6 飞书文档交付审阅]
    I --> J[STEP6.5 推送未发布文稿]
    J --> K[STEP7 发布前 Checklist]
```

各步职责与价值：

**STEP 0 内容安全审查（最高优先级）。** 这是整个 Skill 最有特色的一步。它把公众号审核的「叙事角度」风险前置处理掉，凡是中美政治叙事、芯片管制博弈、时政人物评价、军事安全类内容，都会在动手写之前被拦截并建议改成商业/技术/行业角度。后面单开一节讲。

**STEP 1 确认写文参数。** 写作前主动向使用者收集五个参数：主题、写作风格、排版参考账号、核心观点 Thesis、目标字数。设定理由是「不猜测，主动确认」，避免 AI 擅自假设导致方向跑偏。

**STEP 2 匹配内容骨架。** 根据主题从 5 种骨架里选一种最匹配的：战略拆解型、人物特写型、行业变局型、产品逻辑型、创投生态型。每种骨架对应一个 `playbook_*.md` 资源文件。用户指定「晚点风格」时，从 STEP 3 起会改为调用另一个 `latepost-writer` Skill 的六步写法——这是组合使用，不是本 Skill 原生内置。

**STEP 3 素材采集 + 正文写作。** 采集要覆盖官方渠道、权威媒体、数据报告、社区讨论和海外视角，并把项目信息写进正文，正文按「记者观察叙事」，禁止导师说教口吻。

**STEP 4 生成配套内容包。** 正文一写完整就同时产出三个标题备选（悬念型/数据型/情绪型）、CTA 关注话术、以及 50—80 字可直接复制的朋友圈转发文案。这样使用者不用再补料，文案和文章一次到位。

**STEP 4.5 封面图生成。** 这是它反复强调「不要等提醒再做的必做项」。能调用生成模型就用 `gpt-image-2` 按 1536×656 生成；否则退回用 HTML + Playwright 截图成 900×383 的 PNG。封面图是公众号刚需，所以被硬编码进流程。

**STEP 5 排版交付。** 用脚本把正文注入在线 Markdown 排版站点 md.doocs.org，截图确认渲染，然后使用者到浏览器复制粘贴进公众号后台，手动把小标题改成橙色。

**STEP 6 飞书文档交付。** 先通过飞书建文档 + 插封面图 + 授权，把成稿交给使用者审阅。项目设定「先交付审阅，不直接推公众号」。

**STEP 6.5 推送文稿到公众号。** 本地调用 md2wechat 命令把稿子推成公众号的未发布文稿。这一步需要公众号凭证，标题被限制在 32 个中文字符以内，正文中明确提示封面图参数缺了会直接报错。

**STEP 7 发布前 Checklist。** 输出一张标准核对表，列清楚标题、摘要、排版、封面、分组、CTA、朋友圈文案、发布时段这些「发布前要盯的项」，再让使用者手机预览一遍。

## 三、最值得学的地方：把「安全红线」焊进流程最前端

公众号写作最大的隐形成本其实是「不能发」。这个 Skill 把这个点提前到了 STEP 0，作为最高优先级的一步，结构上用心：

- **不是事后回收，而是写作前拦截。** 安全红线在确认主题、写第一个字之前就扫一遍素材，发现敏感就把角度改掉。
- **判断标的不一样。** 它把审核规则总结成一个可执行公式：先判断文章会不会让读者读出「站一方批另一方」的叙事角度，再判断是不是落在纯商业、纯技术、纯行业趋势的安全选题里。也就是说，审核卡住文章的时候，卡住的往往不是事实本身，而是叙事角度。
- **遇到踩线内容主动预警，而不是等使用者自己发现。** 谁最该对「发不出去」负责，在流程里一开始就写清楚——所以把预警责任明确分派给当前这一步，而不是留给卡在后台才发现。

对任何做 UGC / 内容平台、或交给 AI 批量产内容的人来说，这一节都可以直接搬走——把「合规角度」拉成流程第一扇门。

## 四、一次完整案例：从头到尾走一个真实主题

用一个「战略拆解型」主题走一遍这个 Skill 的标准动作，能看到每一个输入、每一次产出。

**问题。** 要产出一篇「某消费硬件公司的战略决策」方向的公众号推文，从主题到能粘贴进后台的排版稿，中间还缺大量中间产物。

**输入。** 写作参数：主题「某公司放弃价格战的战略选择」、写作风格「通用」、排版参考账号「第101个机器人」、核心观点「主动放弃价格战，是把资源转向做壁垒」、目标字数「长文 3000 字左右」。

**流程产物（每步都落在可见的东西上）。**

1. 安全审查：该选题是纯商业判断，不碰政治/管制，放行进入下一步。
2. 骨架匹配：命中「战略拆解型」`playbook_strategy.md`，按它规定的章节展开公司路径与战略决策。
3. 采集 + 写作：按官方/媒体/财报渠道采素材，采用记者观察式写法输出正文，文中数据必须带出处、不捏造。
4. 内容包：一次性给出 3 个标题方向——悬念型（"这家公司为什么主动放弃价格战？"）、数据型（用营收与市场排名做钩子）、情绪型（引发行业焦虑），外加一段 CTA 和 50—80 字的朋友圈文案。
5. 封面：生成 1536×656 或 900×383 的封面图。
6. 排版：注入 md.doocs.org，小标题手动改橙色。
7. 交付：上传飞书文档给使用者审阅。
8. 推送：md2wechat 推成未发布文稿（凭证必需，缺封面会报 `MISSING_COVER_IMAGE`，标题 ≤32 中文字符）。

**验证与产出。** 这条链路所有环节真跑通，才能得到一篇「内容文案 + 配套物料 + 排版 + 未发布文稿」齐整的公众号文。以上多步依赖使用者本机的第三方通道与公众号凭证，本文并未在本环境实测这些命令的实际输出，流程与命令取自项目官方指令。

**边界。** 若磁盘上没有配置公众号凭证，链路会卡在 STEP 6.5；若没配生成模型 API Key，封面图退化为截图方案；标题超过 32 字 WeChat 会拦截。这几个都是有明确报错边界的闸口，不是隐藏坑。

**迁移场景。** 任何想用 AI 批量生产公众号 / 博客 / Newsletter / 知乎内容的团队，都可以把这套「安全审查 → 骨架匹配 → 内容包 → 封面 → 发布 Checklist」的骨架搬到自己流程里，缺什么补什么，而不用从零搭。

## 五、边界与组合使用

把自动化的那部分"拼图"讲清楚，避免误以为这是独立发光的东西：

- **它不是网站，不是排版平台，也不是发稿 API。** 它的本职工作是把流程编排成一步步交给 Agent 执行，真正触发排版、推送、封面截图网页的都是它外部调用/组合使用第三方通道。这些步骤对本机环境依赖很强，换了机器多半要重配凭证。
- **「晚点」风格不是自带能力，而是把写作模块换成了另一个 Skill。** 触发晚点风格时，真正执行的是 `latepost-writer` 的写作逻辑，当前 Skill 只负责调度与承接它的产物。这属于组合使用。
- **素材写作口吻（记者式观察、禁止导师腔）是它自带的风格要求，不是某个外部模型能力。** 这属于这个 Skill 自己的编排规则。
- **涉密与私有环境信息一律不展开。** 官方指令里出现过的公众号凭证、本地环境文件路径等均属作者本机私有信息，这里不列出、不引用具体值。

## 六、下一步

按三步把它交给读者：先装进 Claude Code 这类 Agent；再用它跑一遍「写作参数 → 得到配套文稿」的走查；最后把「安全审查 + 内容包 + Checklist」这三个结构迁到自己手里的内容流程，把「让 AI 写一篇文章」改成「让 AI 生产一份内容」。

```
wechat-article-writer
    └── STEP 3 写作模块（可切换）
            ├── 默认：通用写作逻辑
            └── 晚点风格：调用 latepost-writer
```
