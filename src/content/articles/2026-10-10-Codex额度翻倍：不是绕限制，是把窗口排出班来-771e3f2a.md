Codex 还没把活干完，额度先见底。遇到这种情况，先看任务怎么安排、模型怎么选，再考虑加预算。

只发一句“帮忙优化这个项目”，它得先扫文件、猜目标，再等你补需求。中途换方案，还得再改一遍。额度就这样花在了来回确认上。

## 按恢复时间安排任务

ChatGPT Work 和 Codex 共享额度。当前官方说明中，Plus 和标准 Business 有五小时使用窗口；Pro 当前没有五小时限制，周额度等限制仍需查看账户用量页。[官方额度说明](https://learn.chatgpt.com/docs/pricing)

网上有一种做法：清晨先让 Work 跑一次定时任务，尝试把窗口起点提前。但官方文档没有确认“发一条消息就能把当天窗口固定排成 5、10、15、20 点”，也不能据此保证额度翻倍。

更实用的是看用量页显示的恢复时间，把重构、调试等重任务排在额度恢复后。定时任务可以安排有用的准备工作，比如整理待处理问题；网页云端任务不用本地开机，涉及本地文件的桌面任务则需要电脑和应用保持运行。[定时任务说明](https://learn.chatgpt.com/docs/automations)

## ChatGPT 目前怎么选模型？

先分清入口：普通 Chat 用来问答、改稿；Work 和 Codex 用来执行任务。GPT-6.1 Sol、GPT-6 Sol、GPT-6 Luna 属于 Work/Codex，不能照着这张表去普通 Chat 里找。模型是否可选，还取决于套餐和上线进度。[模型说明](https://learn.chatgpt.com/docs/models)

| 模型 / 入口 | 适合什么任务 | 选择建议 | 省 token / 额度怎么看 |
| --- | --- | --- | --- |
| Chat 的 Instant 快速模型 | 日常问答、翻译、短文润色 | 简单对话先用它 | 优先简短回答；不能直接套用 Codex 额度规则 |
| GPT-6 Luna（Work/Codex） | 摘要、提取、格式转换、局部代码修改 | 明确、重复的小任务优先 | 这组 Work/Codex 模型中，标准速度下每 token 信用点费率最低 |
| GPT-6.1 Sol（Work/Codex） | 日常开发、多文件修改、持续处理文档 | 多数工程任务的首选 | 能力与成本较均衡，不保证每次 token 数最少 |
| GPT-6 Sol（Work/Codex） | 常规开发与文档任务 | 没有 6.1 Sol 时可用 | 标准输入、输出费率与 6.1 Sol 相同，缓存输入更贵 |
| GPT-6 Astra | 难调试、复杂研究、跨工具完整任务 | 难题再上，先从 Light 开始 | 标准费率更高，需要结合返工成本判断 |

Instant 的底层版本会更新，表中不把 API 别名当成 Chat 的界面名称。[Instant 模型说明](https://developers.openai.com/api/docs/models/chat-latest)

**如果问“哪个最省额度”，明确的小任务优先 Luna；如果问“哪个最省 token”，官方没有同任务的统一排名。**便宜的模型也可能因为返工消耗更多 token。

减少 token 更直接的办法：只给相关文件，限定回答长度，推理强度按任务需要调整。更高推理强度会使用更多 token；速度选 Standard，Fast 会更快消耗额度。[模型设置](https://learn.chatgpt.com/docs/models) · [费率与用量规则](https://learn.chatgpt.com/docs/pricing)

## 开工前，把任务说清楚

不用写很长，讲清目标、范围和验收就够了：

```text
先读 README、AGENTS.md 和相关模块。
目标：修复登录超时。
范围：只改登录模块，不动其他页面。
验收：复现问题，修复后跑相关测试。
交付：改动摘要、验证结果、未解决的问题。
```

这比一句“修一下”更容易让任务一次完成。相关日志给出报错附近的内容，输出只要必要的改动和验证结果，别让模型反复读无关材料。

下一次开工，先用 Luna 处理明确的小任务，日常工程用 6.1 Sol，卡住的难题再交给 Astra。额度仍然长期不够，再比较升级套餐或购买附加信用点的成本。
