# OpenClaw 2026.2.19：Apple Watch 进场，Agent 开始“可随身” & OpenClaw-2026.2.19.dmg 介绍

OpenClaw 2026.2.19 这版的关键词，不是“又加了几个命令”，而是：**把 Agent 的入口往“随身设备”推进了一步**。

结论先放前面：

- 如果你在用 iOS 节点（OpenClaw iOS app 作为 node），这版的 **APNs 唤醒 + 自动重连**会明显减少“后台不响应”。
- 如果你想要“抬手就能看通知/快速回一句”的体验，**Apple Watch companion MVP**值得关注（但它目前是 MVP：能用、别指望完美）。
- 如果你管理多设备/多入口，这版加了 **paired device 清理命令**，终于不用靠“删配置重来”这种原始人操作。
- 如果你走 Telegram，这版把入站一致性、topic 投递、报错噪音都顺了一遍。

下面按「对你有什么用」来拆解 release notes（来源：GitHub release v2026.2.19）。

---

## 1）Apple Watch companion MVP：不是“手表上跑大模型”，是“手表上有个收件箱”

这版新增的是 **Apple Watch companion MVP**，包含三块能力：

- **watch inbox UI**：手表端的收件箱界面
- **watch notification relay handling**：iPhone → Watch 的通知转发链路
- **gateway command surfaces for watch status/send flows**：给网关侧留了 watch 状态/发送相关的指令面

把它翻译成人话：

> 手表不会替你推理。
> 手表做的是“最后一厘米”：把你最关心的通知、收件、快速回复挪到手腕上。

适合什么场景？

- 你在路上/开会/带娃：不方便掏手机，但又想知道“任务有没有跑完”。
- 你把 OpenClaw 当自动化中枢：希望关键提醒能“贴身到腕”。

踩坑预警（MVP 的基本修养）：

- **权限**：通知不通，80% 是系统权限没开。
- **后台唤醒**：iOS 在后台时很多事情本来就容易睡死，这也是下一节 APNs 的意义。

---

## 2）iOS 节点稳定性：APNs 唤醒 + 自动重连，专治“后台装死”

如果你用过 iOS 端当 node，大概率见过这种场景：

- 你在电脑上调用 `nodes.invoke`
- 结果 iPhone 在后台睡死，invoke 失败
- 你开始怀疑人生（以及怀疑 Wi‑Fi）

2026.2.19 做了两件关键事：

1) **在 `nodes.invoke` 前尝试通过 APNs 唤醒断连的 iOS 节点**
2) **静默推送唤醒后自动重连 gateway session**

一句话：把“成功率”从玄学往工程拉。

这对你意味着什么？

- 你可以更放心地把 iPhone/iPad 当成“常驻节点”，去做通知、快捷操作、甚至某些权限型能力（取决于 OpenClaw iOS app 暴露的能力）。

---

## 3）设备管理终于像样了：paired-device hygiene flows

这版加了配对设备的清理/移除能力：

- `device.pair.remove`
- `openclaw devices remove`
- `openclaw devices clear --yes [--pending]`

为什么这很重要？

因为多设备时代的真实问题不是“配不上”，是：

- 你换了手机/重装了 app
- 你 profile 太多，配对表乱成一锅粥
- 你想撤销某个设备的 token，但不知道该删哪条

以前常见的做法是：删库跑路（删配置/重置）。

现在起码可以：**定点清理**。

建议你升级后做一次卫生检查：

```bash
openclaw devices list
```

把不再使用的设备条目清掉，别给未来埋雷。

---

## 4）Telegram 用户看这里：入站一致性 + topic 投递 + 少点噪音

这版对 Telegram 的改动属于“你不一定会注意，但你会更舒服”：

- `message` 与 `channel_post` 走同一套入站处理链路（去重/权限/媒体一致）
- Cron/Heartbeat **明确支持 Telegram topic 目标**（`<chatId>:topic:<threadId>`），定时消息不会乱飞到最后活跃线程
- exec/bash 工具失败提示默认更克制（verbose 才喷诊断），聊天不再像 CI 日志

如果你把 Telegram 当主入口，这些都是稳定性红利。

---

## 5）安全与审计：这版的“真实主角”其实是安全加固

release notes 里安全相关内容非常多，我建议你只记住三条对日常最有用的：

1) **Gateway auth 默认更稳**：未解析时默认 token 模式，并自动生成/持久化 `gateway.auth.token`。
2) **暴露风险会被审计点名**：当 `gateway.auth.mode="none"` 且 HTTP API 可达时，会出现 `gateway.http.no_auth` 级别的发现（含 loopback/远端暴露不同严重性）。
3) 大量 SSRF/注入/插件信任边界的加固：这类东西不性感，但能救命。

一句话建议：

> 你可以不开新功能，但别忽略安全默认值的变化。

## 6）升级后我会做的 5 分钟检查清单（照抄即可）

| 检查项 | 命令/动作 | 你在确认什么 |
|---|---|---|
| 版本 | `openclaw --version` | 真升级了，不是心理安慰 |

## 7）这版带来的一个趋势：Agent 不再只活在电脑里

Apple Watch 这次更像“插旗”：

- 电脑端负责复杂交付
- 手机端负责节点能力与随身连接
- 手表端负责最后一公里的提醒和快速处理

你会慢慢发现：真正的 Agent 不是“多聪明”，而是“随时能接上、而且不打扰”。

## 8）OpenClaw-2026.2.19.dmg 介绍 



**OpenClaw-2026.2.19.dmg** 是给 **macOS 的图形客户端（OpenClaw.app）** 用的安装包（Disk Image）。



它不是“模型/插件包”，而是把 OpenClaw 的 **菜单栏伴侣 App** 打包成你熟悉的 macOS 安装形式，主要作用：



### 这个 dmg 装上后能干什么



根据官方 macOS app 文档（docs/platforms/macos.md）它负责这些关键能力：



1. **菜单栏状态 + 原生通知**



• 在菜单栏显示 OpenClaw 状态

• 用 macOS 原生通知推送消息



2. **统一处理 macOS 权限（TCC）**



• 通知、辅助功能、屏幕录制、麦克风、语音识别、AppleScript 自动化等权限

这些权限很多都需要 GUI App 来弹系统授权框，CLI 自己搞不定。



3. **管理/连接 Gateway（本地或远程）**



• Local 模式：帮你启动/挂接本机 Gateway（launchd）

• Remote 模式：连接远端 Gateway（SSH/Tailscale），本机不必跑 gateway



4. **把这台 Mac 暴露成一个“节点（node）”给 Agent 用**

从而让 Agent 能调用 macOS 专属能力，例如：



• system.run / system.notify

• screen.record

• camera.snap / camera.clip

• Canvas / UI 自动化相关能力（取决于你是否启用）



### 什么时候需要下载 dmg



• 你想用 **屏幕录制、摄像头、系统通知、UI 自动化** 这类 macOS 能力

• 你想要一个“常驻”的 OpenClaw 控制面板，而不是纯终端

• 你用远程 Gateway，但希望远程也能调用你这台 Mac 的 node 能力



### 什么时候不一定需要



• 你只在服务器上跑 gateway，只通过 Telegram/CLI 聊天，不需要 macOS 权限能力

这种场景 npm 安装 CLI 就够了。
