# **Mac 终端启动慢到离谱？我以为电脑坏了，结果是我自己在** 

# **.zprofile**

#  **里“疯狂加班”**

先说结论：

* *困扰我很久的 Mac 终端启动慢问题，今天终于被我干掉了。**

以前我每次开终端的体验都像这样：

- 打开终端
- 等
- 继续等
- 我开始怀疑人生
- 我甚至怀疑苹果是不是偷偷给我换了个诺基亚芯片

最离谱的是，我跑一个简单命令：

```
zsh -lc 'echo ok'
```

它居然要 **1 分 23 秒**。

我当场就想给它开追悼会。

但事实证明：

* *不是电脑慢，是我自己写的启动配置在作妖。**

## **✅ 1）先确认问题：终端到底慢在哪？**

很多人一说“终端慢”，其实只是在骂情绪，没抓到证据。

所以第一步要做的是：**量化它到底慢多少。**

我跑了这个命令：

```
time zsh -lc 'echo ok'
```

输出是：

> **1:23.04 total**

这一下就很明确了：

不是“感觉慢”，而是**确实慢到离谱**。

## **✅ 2）第一层误判：我以为是** 

## **.zshrc**

##  **的锅**

因为大多数人终端慢，最常见的原因就是：

- oh-my-zsh 插件太多
- compinit（补全系统）太重
- nvm/conda/pyenv 启动像拖拉机

于是我用性能分析工具直接开挖：

```
zsh -i -c 'zmodload zsh/zprof; source ~/.zshrc; zprof'
```

结果出来一看，确实很像“补全系统背锅现场”：

- compinit
- compdump
- compdef
- compaudit

补全这套东西耗时夸张到像：

> 你只是想打个 ls，它先把整个银河系索引一遍。

所以我当时的判断是：

✅ “问题是补全系统导致的”。

然后我做了一个尝试：优化 .zshrc，让 compinit 走缓存，减少安全扫描。

（这个方向没错，但关键点是：**它解决不了 zsh -lc 的慢**）

## **✅ 3）关键转折：为什么改** 

## **.zshrc**

##  **没用？**

因为 zsh -lc 这个东西非常阴险，它不是普通交互终端。

它是：

- -l：login shell（会加载 .zprofile）
- -c：执行命令后退出（非交互）

⚠️ 它通常 **不会加载 ~/.zshrc**。

所以你在 .zshrc 里怎么改，有时根本影响不到它。

也就是说：

> 你以为你在修发动机，

> 其实你一直在擦车玻璃。

## **✅ 4）精准定位：凶手其实在** 

## **.zprofile**

于是我打开了自己的 .zprofile 看了一眼。

我看完沉默了三秒。

因为它长这样（重点来了）：

```
eval "$(/opt/homebrew/bin/brew shellenv)"
eval "$(/opt/homebrew/bin/brew shellenv)"
eval "$(/opt/homebrew/bin/brew shellenv)"
...
（重复了差不多 20 次）
```

我当场悟了：

> 原来不是终端慢，

> 是我每次启动终端，都让 Homebrew 重新“入职培训”了 20 次。

而 brew shellenv 干的事情是：

- 重算 PATH
- 重设环境变量
- 输出一堆 export
- 你执行一次没啥
- 你执行 20 次就是自杀式加班

于是每次 zsh -lc 都会加载 .zprofile，然后它就开始：

> “好的，我先把环境变量反复算 80 遍，再给你 echo 一个 ok。”

你说它能不慢吗？

它都快累哭了。

## **✅ 5）修复方案：删掉重复的** 

## **brew shellenv**

## **，并加一把“非交互跳过锁”**

我的目标很明确：

1. brew shellenv 只执行一次
2. Codex / 工具类的非交互 shell 不加载重配置
3. 保留我正常终端的体验

最终我把 .zprofile 改成了这样：

```
# Fig pre block. Keep at the top of this file.
 -f "$HOME/.fig/shell/zprofile.pre.zsh"  && builtin source "$HOME/.fig/shell/zprofile.pre.zsh"

# If NOT interactive, skip heavy init (speeds up zsh -lc for tools like codex)
 -o interactive  || return 0

# Setting PATH for Python 3.8 (keep if you still use it)
export PATH="/Library/Frameworks/Python.framework/Versions/3.8/bin:$PATH"

# Homebrew bottles mirror (optional)
export HOMEBREW_BOTTLE_DOMAIN="https://mirrors.ustc.edu.cn/homebrew-bottles/bottles"

# Homebrew environment (run ONCE)
eval "$(/opt/homebrew/bin/brew shellenv)"
```

你看到没？

- 不再重复执行 brew shellenv
- 加了一句非常狠的判断：

```
 -o interactive  || return 0
```

意思是：

> 你不是交互式终端？那别来烦我，直接跳过重配置。

这句是关键，它能让很多工具型命令恢复速度，包括但不限于：

- codex
- git hooks
- 各种脚本工具
- 一堆你没意识到会开 shell 的程序

## **✅ 6）验收：从 83 秒 → 0.018 秒**

改完之后，我再跑一次：

```
time zsh -lc 'echo ok'
```

结果：

> **0.018 total**

那一刻我甚至有点不适应。

因为我已经习惯了：

- 打开终端
- 去倒杯水
- 回来它还在加载

现在它秒开了，我反而不知道要干嘛了。

## **✅ 7）这件事最值得记录的经验：终端慢，不要瞎猜，要用“证据链”打穿**

这次排查让我印象最深的一点是：

很多时候你以为是 A 的锅，

但真正的凶手是 B。

我这次的证据链是：

1. **量化慢**：time zsh -lc 'echo ok'
2. **性能分析**：zprof 看 .zshrc 内部耗时
3. **理解加载机制**：zsh -lc ≠ zsh -i
4. **精准定位文件**：.zprofile 被加载、重复执行 shellenv
5. **最小改动修复**：删重复 + 非交互跳过锁
6. **再次量化验证**：从 83s 到 0.018s

这才是正确的排查方式：

> 不是靠感觉修电脑，

> 是靠证据把问题按在地上摩擦。

## **✅ 最后一句总结**

如果你觉得终端慢、命令慢、工具超时，先别怪电脑。

你先想想：

> **有没有可能，是你在启动配置里让它每天上 80 次班。**
