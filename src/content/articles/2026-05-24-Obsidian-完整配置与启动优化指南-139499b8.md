## 四、启动慢原因深度诊断

### 🔍 根因分析

你的 Obsidian 启动 **17 秒**，是以下 **四大因素 × 97 个插件** 叠乘的结果：

#### 因素 1：插件数量泛滥（主因）

当前 97 个社区插件，经 Lazy Plugins 检查：
- **84 个插件配置为 "instant"（立即加载）**
- 仅 12 个插件被设为 "disabled"
- 0 个插件被设为 "delayed"（延迟加载）

> 每个插件启动时都会执行初始化代码，即使只是注册一个命令。
> 84 个插件同时初始化 = 每插件算 0.2 秒 = 16.8 秒。

#### 因素 2：重型插件拖累

以下插件在启动时做**额外工作**：

| 插件 | 启动额外开销 |
|------|------------|
| **dataview** | 扫描全库构建索引（数千文件） |
| **omnisearch** | 缓存未启用（`useCache: false`），启动重建全部索引 |
| **smart-connections** | AI 嵌入计算，CPU 密集型 |
| **obsidian-icon-folder / iconic** | 加载图标字体库 |
| **obsidian-git** | 检查 git 状态 |
| **templater-obsidian** | 注册模板命令 |
| **obsidian-excalidraw-plugin** | 加载 Canvas 运行时 |

#### 因素 3：启动恢复标签页

核心插件启用了 `daily-notes`，退出时默认会保存打开的标签页。
当前你可能打开了 **22 个标签页**，启动时需要恢复所有内容。
而 **workspaces 核心插件未启用**，无法设置轻量启动工作区。

#### 因素 4：首页（Homepage）未启用

Homepage 插件已安装，但 `openOnStartup: false`。
退出时如果有多个标签页，下次启动会全部恢复。

## 五、优化方案（按优先级排序）

### ⭐ 第一优先级：立即见效

#### ✅ 1. 启用 lazy-plugins，重新配置

当前 Lazy Plugins 的问题：**84 个插件都是 "instant"**，等于没用。

操作步骤：
1. 设置 → 社区插件 → Lazy Plugin Loader
2. 将以下插件改为 **"delayed"**（延迟 15 秒加载）：

```text
dataview           → delayed
omnisearch         → delayed
smart-connections  → delayed
obsidian-git       → delayed
obsidian-icon-folder → delayed
iconic             → delayed
editing-toolbar    → delayed
obsidian-file-color → delayed
colored-text       → delayed
pretty-properties  → delayed
colorful-note-borders → delayed
cmdr               → delayed
obsidian-better-command-palette → delayed
obsidian-hover-editor → delayed
templater-obsidian → delayed
quickadd           → delayed
obsidian-quiet-outline → delayed
custom-sort        → delayed
virtual-linker     → delayed
```

3. 保留为 "instant" 的只留你最常用的 15-20 个核心插件

#### ✅ 2. 关闭启动恢复标签页

```text
设置 → 编辑器 → 标签页
关闭：启动时恢复上次打开的文件
```

#### ✅ 3. 启用 workspaces 核心插件

```text
设置 → 核心插件 → 工作区 → 启用
```

然后创建一个轻量启动工作区：

```text
工作区（左侧栏）
→ 管理工作区 → 保存
→ 只保留 Daily Note + 文件列表
→ 命名为 "Startup"
```

#### ✅ 4. 开启 Homepage 随启动打开

```text
设置 → 主页
→ 打开 homepage/data.json 直接编辑
→ 设置 "openOnStartup": true
→ 主页设置为：空白笔记 或 简单 Daily Note
```

注意：Homepage 页面建议设置为简单内容，不要放 Dataview 大查询。

#### ✅ 5. 禁用或删除无用插件

立即禁用以下插件（无需卸载，禁用即可）：

### ⭐ 第二优先级：进一步提速

#### ✅ 6. 启用 Omnisearch 缓存

当前 omnisearch 缓存关闭，每次启动重建索引。

```text
设置 → Omnisearch
→ 打开：Use cache
```

只需要一次构建，后续启动直接读缓存。

#### ✅ 7. 清理未使用的插件目录

当前 `plugins/` 下有 **114 个目录**，但 community-plugins.json 只注册了 **97 个**。
多余的 17 个是已删除但残留的插件目录，Obsidian 启动时仍可能会扫描。

可以通过以下方式清理：
```bash
# 先备份
cp .obsidian/community-plugins.json .obsidian/community-plugins.json.bak

# 列出所有已注册插件ID
# 然后删除不在列表中的插件目录
```

或者直接在 Obsidian 中卸载所有未使用的插件。

#### ✅ 8. 设置 Omnisearch 排除目录

在 Omnisearch 设置中，排除不需要搜索的目录：

```text
排除：90-Archive, 99-Attachments, .git, node_modules
```

### ⭐ 第三优先级：长期维护

#### ✅ 9. 安装/配置 Lazy Plugin Loader

你已安装 ✅，只需重新配置。

#### ✅ 10. 减负原则：按需 vs 常驻

问自己：

| 问题 | 如果答案是"否"→ 禁用或延迟 |
|------|---------------------------|
| 你每天用这个插件吗？ | 延迟加载 |
| 它必须开机就工作吗？ | 改为按需 |
| 你记得你装了它？ | 卸载 |
| 它带来的价值 > 它拖慢的启动时间？ | 保留 |

#### ✅ 11. CSS Snippets 精简

当前 snippets：homepage, colored-folders-No Background, line-spacing, md, highlight-fix

检查 `colored-folders-No Background` 和 `md` 是否还在用，不需要就移除。

但 Comic Sans MS 不是等宽字体，设为等宽字体可能会导致终端/代码块显示异常。
