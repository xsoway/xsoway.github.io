# 牛马别再烧 Token 造平台了，真正值钱的是你的工作流

牛马已经够辛苦了，真没必要再给大家叠加一层又一层的平台、规范和流程。

AI 时代最有价值的，不是再造一个平台，也不是给旧系统套一层聊天框，而是提供真正好用的 Tool、Skill 和 CLI，把选择权还给用户，把自由度留给开发者。

好用的东西，从来不需要靠行政命令推广。谁能解决问题，谁就会被接入，谁能提升效率，谁就会被传播。

可现实里有些项目一上来，画风就很熟悉。先搭一个平台，再定一套规范，然后要求所有人接入，折腾一圈以后才发现，原来的工作并没有变轻，只是在提交任务之前多填了一张表，执行任务之后多截了两张图。

表面上是在建设生态，实际上是在建设工作量。

更让人无语的是，大家都在用 AI 提效，有人在用 AI 加班造平台。大家都在造工具，有人在造一套管理工具的工具。大家都在解决问题，有人忙着解决一个从来没有出现过的问题。

重复套壳、反复造轮子、自我感动式创新，很多时候和生产力提升没有太大关系，更像是一场技术人的大型行为艺术。演出的人很投入，台下的人只想早点下班。

真正优秀的产品其实只有一个标准，用了以后大家离不开，而不是不用以后领导离不开。

说真的，我非常理解大家为什么喜欢造平台。

一个脚本解决了问题，看起来只是一个脚本。一个接口省掉了半小时，好像也很难在汇报材料里讲出气势。可一旦给它加上首页、登录、菜单、看板、任务中心和数据大屏，事情立刻就不一样了。

平台两个字，自带一种工程完成度。哪怕里面真正有价值的逻辑只有两百行代码，只要外面包上完整的系统壳子，截图放进汇报里就会显得特别像一件大事。

AI 又把这件事推得更远。以前一个人想做完整平台，光是前后端、数据库、部署和权限就能把热情耗掉一半。现在有 Claude Code、Codex 和各种大模型帮忙，页面可以生成，接口可以补齐，部署脚本也有人代写。很多过去不值得做的东西，突然变得好像做得出来了。

注意，是做得出来，不一定是值得做。

这两个判断差得非常远。

尤其在测试行业，这种错位会更加明显。很多公司本来就有成熟的企业级自动化平台，权限管控、任务调度、用例管理、批量执行、数据统计、运行告警和日常运维都已经有人负责。团队里的常规接口自动化、固定回归、标准报表和标准化数据校验，也早就在这套基建上稳定运行。

然后有同事花自己的时间、烧自己的 Token，从登录页开始，重新做一遍。

我不是反对自研，更不是觉得技术人不该折腾。恰恰相反，我一直觉得技术人应该保留折腾东西的冲动，那是很多好产品的起点。但折腾之前至少要问清楚一件事，我现在做的东西，到底是在补一个真实缺口，还是仅仅因为大模型让重复建设变容易了。

如果公司已经有一套成熟、稳定、合规而且免费的公共平台，个人再复刻一套架构完整、功能重叠的版本，最大的问题不是技术做不到，而是做完以后几乎没有新增价值。

官方平台有多租户体系、服务部署、调度引擎、数据存储、权限管理、故障兜底和团队协作流程，这些能力并不是页面上几个菜单的总和，而是长期运维、组织规则和责任边界共同堆出来的结果。个人版本可以把界面复刻得很像，也可以跑通几条漂亮的演示流程，但只要进入真实团队协作，权限怎么管、失败怎么兜、数据怎么留、服务挂了谁来修，这些问题会一个接一个冒出来。

更麻烦的是，个人版平台会持续吞噬注意力。功能刚跑通时要调试，模型升级后要适配，接口变更后要修复，服务异常后要排查。每一次调用还在烧自己的 Token。最开始只是想省一点工作时间，后来却多了一套需要照顾的系统，白天给公司平台处理任务，晚上给个人平台处理故障。

这不是提效，这是给自己新增了一个没有工资的运维岗位。

而且这种完整复刻很难变成真正的职场壁垒。因为它解决的是一个团队已经解决过的问题，产出和现有能力高度重叠。别人只要愿意投入类似时间，也能再做一套。你确实证明了自己会写代码、会搭服务、会调用模型，但很难证明这套东西让业务多获得了什么。

可问题聊到这里，很容易又滑向另一个极端。既然公司已经有平台，那我什么都不做，所有需求都等公共平台支持，岂不是最省事。

也不对。

企业平台强在稳定、合规和统一，它天生要照顾大多数人的共同需求。只要一个能力要进入公共平台，就要考虑权限、兼容性、稳定性、使用门槛、维护成本和推广范围。这个过程没有错，但它决定了公共平台很难快速响应每个人眼前那些很小、很急、很偏的需求。

测试工作里偏偏到处都是这种需求。某一批异常数据需要临时清洗，一个线上偶现问题需要定向复现，一种非标对账逻辑只在特定业务里使用，一份专项复盘需要按照自己的判断方式生成，还有一些风险排查规则，只有长期跟着业务的人才知道该从哪里下手。

这些事情放进企业平台，可能排不上优先级，也可能根本不值得做成公共功能。但对正在处理问题的人来说，它们又确实反复出现，每次都在消耗时间。

所以真正值得自研的，从来不是另一套企业平台，而是这些公共基建没有覆盖到的单点能力。

你可以写一个专项数据清洗脚本，可以封装一个非标对账接口，可以做一个针对特定故障的复现工具，也可以把自己的风险研判逻辑整理成一个可调用模块。它们不需要首页，不需要用户中心，更不需要为了显得完整，再给自己补一个运营后台。

它只需要解决问题。

我很喜欢这种轻量自研方式，因为它的目标非常克制。不造基建，只造能力，不跟企业平台抢它已经做好的事情，只去补那些标准化流程顾不到的缝隙。

一个好的个人能力模块，最好还满足三个条件。输入边界清楚，别人知道应该给它什么。输出结果稳定，别人能判断它有没有完成任务。调用方式足够简单，可以是接口、CLI，也可以是一个独立 Skill，不需要先学习一整套平台才能使用。

这样的东西虽然看起来没有大屏震撼，却更容易产生真实价值。今天你自己调用，解决一个高频痛点。明天同事发现好用，直接把接口接进他的流程。再往后，如果它确实具备普遍价值，还可以交给公共平台团队治理，补齐权限、监控和稳定性以后，变成团队资产。

个人自研最健康的成长路径，不是从脚本一路膨胀成个人平台，而是从一个真实问题出发，先做出足够小的能力，再让被验证过的能力进入更大的系统。

补位，不重复。创造增量，不制造内卷。

顺着这件事继续往下想，还有一个更容易被忽略的问题。Tool、接口和 CLI 解决的是事情能不能做，但真正拉开人与人差距的，往往不是拥有多少工具，而是知道什么时候该用哪个工具，以及应该按什么顺序把它们组合起来。

同样拿到一份需求，有人先看文档，再机械执行用例。有人会先查历史 Bug，判断高风险模块，再看代码变更影响范围，补充边界场景，执行回归，最终把证据和结论整理成报告。

他们可能使用同一套企业平台，也拥有同样的接口权限，但产出质量完全不同。差别藏在一个人的判断顺序、排查习惯、避坑规则和交付标准里。

以前这些东西很难复制，只能靠师傅带、自己悟，或者在一次次事故里慢慢长记性。AI Agent 和 Skill 出现以后，我们终于有机会把它们从脑子里的经验，变成可以重复执行的个人 SOP。

企业平台提供公共能力接口，个人自研负责补齐那些小而重要的缺口，Agent 则按照你的工作方法，决定什么时候调用哪些能力，怎样检查结果，遇到异常走哪条分支，最终按照什么标准交付。

这时候，AI 不再只是帮你写一段代码或者生成一份报告，它开始适配你的做事方式。

举个不需要编造具体经历的测试流程。拿到一次提测以后，Agent 可以先读取需求和 diff，再调用企业平台查询历史用例、回归结果与缺陷记录。如果公共平台没有对应的专项分析能力，就继续调用你自己封装的风险研判接口。结果出来以后，它按照你沉淀在 Skill 里的规则检查遗漏项、标记待确认风险，并生成符合团队格式的测试执行清单。

这里面最值钱的不是 Agent 会调用接口，任何人看一遍文档都能学会。真正值钱的是你知道应该先查什么、什么结果不能直接相信、哪些边界必须人工确认、怎样的报告才算可以交付。

工具是公共的，方法是你的。

我有时候觉得，这才是 AI 时代技术人真正该积累的东西。不是比谁搭的平台更大，也不是比谁一天烧掉的 Token 更多，而是看谁能把自己的业务经验整理成稳定流程，把一次性的判断变成可复用能力，再让这些能力随着工作持续更新。

当然，这条路也没有听起来那么轻松。把经验写成 Skill，并不是把几句提示词扔进文件里就结束了。你需要明确输入输出，需要把模糊判断拆成规则，需要记录失败案例，也需要持续检查 Agent 有没有在错误的地方自作聪明。

一开始甚至可能比手工做更慢，因为你得把过去凭感觉完成的动作，一个个说清楚。但这部分时间没有花在重复造壳子上，而是花在理解自己的工作上。只要流程真的稳定下来，它就能一次次复用，并且随着你的经验持续进化。

回到开头那句吐槽，牛马已经够辛苦了，别再给自己搭一座需要长期维护的平台。

公司成熟的企业平台，该用就用，它负责稳定、统一和合规。公共平台覆盖不到的高频缺口，该做就做，但尽量做成轻量、独立、可接入的能力。真正值得长期投入的，是把自己的判断逻辑、业务经验和交付标准沉淀成 Agent 能执行的 Skill 与 SOP。

公共平台是地基，个人自研是插座，Agent SOP 才是你自己的工作方式。

地基没有必要每个人都重打一遍，插座也不需要盖成一栋楼。你真正应该带走的，是那套知道电该接到哪里、设备该怎样运转、出了问题该怎么检查的方法。

AI 时代的测试竞争，早就不只是看谁会写脚本、谁会搭平台。真正拉开差距的，是谁能拒绝无效消耗，谁能把个人经验变成可复用资产，谁能让公共能力、单点工具与自己的工作方法真正配合起来。

停止烧 Token 复刻一套大而全的平台，也别躺在公共工具上等所有问题自动消失。

让企业平台承接标准化工作，让个人自研创造真实增量，再让 Agent 按照你的 SOP 把它们串起来。

这样做出来的东西，也许没有一个巨大的首页，没有十几个漂亮菜单，甚至不太适合放进汇报材料里炫耀。

但它会真的帮你少加班，也会让别人逐渐离不开你的能力。

这就够了。
